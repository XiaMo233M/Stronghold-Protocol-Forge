# START-HERE —— 完全不会的人，从这里开始

> ⚠️ **同步纪律：这份文件与 Mods 仓（`Stronghold-Protocol-Forge-Mods`）的 `BEGINNER.md` 同源。**
> 两份是**同一份内容的两个落点**：这里是**引擎包内**那一份（`app\docs\START-HERE.md`），
> 那边是**仓库检出**那一份。**改了一边必须改另一边。**
> 差异只有两处，都是路径口径：本文件按**整合包根**叙述（`app\docs\…`、`app\workshop\…`），
> 那边的相对链接指向 Mods 仓自己（`SKILL.md`、`UPLOAD.md`、`site/README.md`）。
> `docs/errors.md`、`docs/task-01-换个立绘.md`、`docs/task-02-加个干员.md` 同样是两边同步的。
>
> **这是给「做包的人」的唯一入口。** 你不需要读任何别的文档就能做完第一个包。

- **你要做的事**：做一个工坊包，装上之后游戏里的某个东西变成你自己做的。
- **需要什么**：一个能玩的整合包（`…-win-x64.zip`）；一张 PNG 图；10 分钟。
- **花多久**：第一次 5～10 分钟，大部分时间在找图片。

> 不懂 JSON、不会写代码，都不影响。下面每一步都给了可以**原样复制**的命令和文件内容。
>
> **这份文件只管「怎么做」。** 格式的完整规则、每一个字段的完整定义**不在这里**，
> 以引擎文件为准，见文末[附录 C](#附录-c--想要更多细节去哪儿)。
> 本文不复制引擎文档，免得出现第二份会过时的说明。

## 一、先说清楚：一个包是什么

**一个包 = 一个文件夹 + 一个 `pack.json`。** 就这两个东西，没有别的。

```
my-first-pack/          ← 包文件夹（名字 = 下面 pack.json 里的 "id"）
├── pack.json           ← 唯一要改的文本文件（7 行）
└── assets/
    └── portrait.png    ← 你要换上游戏的那张图
```

文件夹里的东西放错一层，游戏就看不到这个包。所以记住一句话：

> ⭐ **包文件夹的上一级，就是你的 `workshop` 文件夹。**
> 也就是说，游戏在 `app\workshop\<包 id>\pack.json` 这个位置找包。

## 二、四步跑通

### 第 1 步 · 复制模板

| | |
|---|---|
| **输入** | 整合包根目录的 [`app\docs\my-first-pack\`](my-first-pack)（就在这份文件旁边） |
| **做什么** | 把 `my-first-pack` 整个文件夹复制到整合包根目录下的 `app\workshop\`（没有 `workshop` 文件夹就自己建一个） |
| **敲什么** | 不用敲命令，用文件管理器复制粘贴 |
| **成功时看到** | `app\workshop\my-first-pack\pack.json` 这个文件能双击打开 |
| **最常见失败原因** | 复制到了 `app\` 下、或者 `app\workshop\` 下又套了一层文件夹 —— 游戏找不到包，而且**不报错** |

模板的 `pack.json` 全文如下。**这就是能直接用的内容，原样照抄，一个字符都不要多**：

```json
{
  "id": "my-first-pack",
  "name": "我的第一个包",
  "version": "1.0.0",
  "author": "你的名字",
  "license": "CC-BY-4.0",
  "description": "把官方干员凯尔希（char_003_kalts）的立绘换成我自己画的一张图。",
  "api": ">=1 <2",
  "art": {
    "chars": {
      "char_003_kalts": {
        "portrait": "portrait.png"
      }
    }
  }
}
```

> ⚠️ **JSON 不能写注释。** 上面这一段里**没有** `//` 开头的内容 —— 请保持这样。
> 仓库里有的文档用 ` ```jsonc ` 写示例，里面带 `//` 注释（例如 `docs/SKILL.md` 那类老文档）。
> 那些是给人看的示意，**照抄进文件会让 `pack.json` 解析失败**。以本段为准。

`my-first-pack` 这个文件夹名**必须和 `pack.json` 里的 `"id"` 一模一样**。
这是整条路上最容易错、后果最重的一处：不一致 = 整个包被跳过，游戏里什么都看不到。

---

### 第 2 步 · 改三处

#### 第一处：文件夹名和 `"id"`

把 `my-first-pack` 改成你想要的包名。**只能用英文字母、数字、下划线、短横线，32 个字符以内，不能用中文。**
`pack.json` 里的 `"id"` 跟着改成同一个词。

> **白话一句**：`"id"` 就是**机器用来认这个包的名字**。人看的是 `"name"`，机器看的是 `"id"`。

#### 第二处：`"name"` 和 `"author"`

写这个包的名字和你自己的署名。**中文随便写。**

#### 第三处：换成你的图，并填对干员 id

1. 把你的图片改名成 `portrait.png`，覆盖掉 `app\docs\my-first-pack\assets\portrait.png`。
   想用别的文件名也行，那就要把 `pack.json` 里 `"portrait"` 后面那个 `"portrait.png"` **一起改掉**，两边保持一致。
2. 把 `"char_003_kalts"` 换成你想要的那个干员的 id。

**干员 id 怎么查？** 在整合包根目录（也就是有 `data\` 和 `tools\` 的那一层）打开命令提示符，粘贴：

```
node -e "const a=require('./data/assets.json');for(const k of Object.keys(a.chars))console.log(k, (a.chars[k].portrait||''))"
```

它会打印全部 210 名干员的 id 和当前立绘路径，像这样：

```
char_003_kalts /assets/char/portrait/char_003_kalts_1.png
char_010_chen  /assets/char/portrait/char_010_chen_1.png
```

找到你要的那一行，把**左边那一串**抄进 `pack.json`。

> `char_` 后面那串数字是**官方编号，不是名字**，所以猜不出来，只能查表。
> 同一个干员做第二次就不用再查了。

| | |
|---|---|
| **输入** | 你的 PNG 图；一个干员 id |
| **成功时看到** | `assets\portrait.png` 是你那张图；`pack.json` 里 `"id"` = 文件夹名，`"char_003_kalts"` 已换成你的 id |
| **最常见失败原因** | ① 图片没放进 `assets\`（或文件夹名打成了 `asset`、`Assets`）⇒ 报 `ART_NEEDS_ASSETS` ② 把 `"license"` 那一行删了 ⇒ 报 `ASSETS_NEED_LICENSE` ③ 干员 id 抄错一位 ⇒ 立绘变了，但变的是别人的 ④ 图的名字和 `pack.json` 里写的不一致（**大小写也算**）⇒ 游戏里还是老图 |

### 第 3 步 · 导出成一个 zip

**方式 A（推荐，不用敲命令）**：双击整合包根目录的 **`启动编辑器.bat`** → 打开**包管理**页面 → 找到你这个包 → 点 **导出投稿件 .zip**。

**方式 B（习惯命令行）**：在 `workshop` 文件夹的**上一级**打开终端，粘贴（把 `my-first-pack` 换成你的包 id）：

```
node tools/workshop-pack.mjs export my-first-pack --out my-first-pack.zip
```

**成功时你会看到**（本项目实测的原样输出）：

```
已导出 my-first-pack：E:\…\my-first-pack.zip
  2 个文件，575 字节
```

**这个 zip 里应该有什么**（实测，`pack.json` **直接在 zip 最外层**）：

```
assets/portrait.png
pack.json
```

> ⭐ **止痛点：用 `workshop-pack.mjs export` 导出，站点要的形状自动就是对的。**
>
> 上传站只认**扁平**的 zip —— `pack.json` 必须直接躺在 zip 的最外层，中间**不能**再套一层文件夹。
> 手工右键压缩时，很多人会把整个文件夹压进去，于是 zip 里变成 `my-first-pack/pack.json`，多了一层，
> 上传被拒。**别手压 zip，用上面两种方式，这个问题不会发生。**

| | |
|---|---|
| **输入** | 改好的包文件夹 |
| **成功时看到** | 一份 `.zip`；打开它，`pack.json` 在**最外层** |
| **最常见失败原因** | zip 里多了一层 `my-first-pack/` ⇒ 上传被判 `WRAPPED` / `HTTP 400`，要求重压 |

### 第 4 步 · 上传

| | |
|---|---|
| **输入** | 上一步那个 `.zip` |
| **去哪** | 项目自带的上传站（地址与部署见源码仓库的 `site/README.md`） |
| **敲什么** | 「mod 名」写你的包名；「备注」照实写来源、作者、许可、改了什么、素材哪来的；选 zip；点**上传** |
| **成功时看到** | 屏幕上出现「收到了。」+ 一个编号 + 一个回执令牌。**把这两行存下来**，之后能查状态 |
| **之后** | 维护者下载跑测试、审过名称与内容之后才会上线。**传上去 ≠ 上线** |
| **最常见失败原因** | ① 文件不是 `.zip` ⇒ `只收 zip。` ② zip 里套了一层文件夹 ⇒ `HTTP 400` ③ 检测到包里含游戏解包素材 ⇒ **照收**，但要在备注里写明「含官方素材」，版权归鹰角网络、仅供非商业使用 |

> **没有站点也能投稿**：走源码仓库 `UPLOAD.md` 那三条路（GitHub 网页 / git / 开 issue）。

## 三、怎么确认它真的装得上（不用开游戏）

在整合包根目录粘贴（把路径换成你自己的 `workshop` 文件夹）：

```
node tools/workshop-validate.mjs app/workshop
```

**本项目实测的原样输出**（就是上面这份模板跑出来的）：

```
workshop root: E:\…\app\workshop

pack my-first-pack (我的第一个包) — 1 art entry
  OK

behaviour layer (kits/):
  (no kits)

0 error(s), 0 warning(s)
VALID: the engine accepts this content.
```

看到 **`0 error(s), 0 warning(s)`** 和 **`VALID`** 就是装得上。这条命令**不写任何文件**，可以随时跑。

> 编辑器里也有这条：**包管理 → 校验这个包**。两条路同一套判据，结果一样。
>
> **改完包，游戏里没变？** 引擎**没有热重载**。关掉窗口重新启动游戏才会看到变化。
> 这一步在老的文档里只写在附注里，所以很多人以为自己做失败了 —— 其实只是没重启。

## 附录 A · 术语对照表（内部词 → 人话）

左边这一列是我们内部的说法，**不该出现在给作者看的说明里**。你在老文档里遇到它们时，照右边这一列理解。

| 老文档里的词 | 人话 |
|---|---|
| **面** | 「能改的东西」。`这个面今天能用` = 这件事今天能做 |
| **覆盖** | 「改掉官方的某一条」 |
| **通道** | 「支持的写法」。`这条通道开着` = 这件事能做 |
| **形状** | 「格式 / 写对没有」 |
| **判据** | 「怎么判断」。`判据是这条` = 看这一条就能判断 |
| **贡献项** | 「这个包实际带到游戏里的东西」。⚠️ 建议直接换成「这个包带来了什么」 |
| **口径** | 「预设方案」（满练度、12 部署位这类可切换的预设） |
| **白名单** | 「只能用的那几个」。`import 白名单` = 只能 import 这 22 个（别名清单见源码仓库 `SKILL.md` §7） |
| **落点** | 「写进哪里」 |
| **闭枚举** | 「只能从这几个里选」 |
| **身份哈希** | 「这个包的指纹」。改了任何东西，指纹就变 |
| **叠加** | 「加进去」（不覆盖官方的东西） |
| **`§1.9.4` / `§28.49` 这类编号** | 忽略。想引用就写「见《包格式》那一节」，或者干脆把话说完 |
| **宿主 lane** | 「这个服务器自己的接口」。**这一格包根本用不了** |
| **三档检查** | 「上传时的自动检查」，三档分别是「会拦你」「要你确认」「只是记一下」 |
| **`PACK_FIELDS`** | 「`pack.json` 能写的字段」 |
| **中间层能力声明** | 「进阶功能」（`assets` / `client` / `server` / `routes`） |
| **声明型** | 「只写声明、不带文件的包」 |
| **wire 契约** | 「客户端和服务器之间的消息格式」 |
| **归一化** | 「读进来整理成统一格式」 |
| **摘要闸门** | 「比对指纹，对不上就不让联机」 |
| **golden 语料** | 「我们的回归测试」。**维护者词，作者文档里应当删掉** |
| **装载器** | 「装包的程序」。`装载器整包跳过` = 这个包装不上 |
| **工坊根** | 「你的 `workshop` 文件夹」 |
| **封闭世界** | 「不能凭空发明字段」 |
| **层（layer A/B/C）** | 「A = 只改数据，B = 改服务端规则，C = 改界面」 |
| **`combat: true`** | 「这个包会改变对局结果」 |
| **点名 / 点名拒绝 / 点名但不拒包** | 「会明确告诉你」/「会告诉你，但不拦你」 |
| **静默** | 「不报错，但也不生效」 |
| **逐字节不变** | 「完全没影响」 |

## 附录 B · 常见错误表（真症状 → 原因 → 怎么改）

按「你在屏幕上看到什么 / 你感觉到什么」查。**逐条错误码的白话解释**见 [`errors.md`](errors.md)。

| 真症状 | 真正的原因 | 怎么改 |
|---|---|---|
| 包装上了，游戏里一切照旧，日志也干干净净 | `content` 里没写 `chess` —— 引擎**只读声明过的文件**，`chess.json` 在磁盘上但一个字节都不读。**症状全是静默的** | 在 `pack.json` 里写 `"content": ["chess"]` |
| 校验说「什么都没带」，可我明明写了 `support` | `support` / `playtest` / `variants` / `behaviour` / `dependencies` / `conflicts` / `callBudget` / `matchKinds` **都不算内容**（八样）—— 它们说的是「怎么跑」，不往对局里带东西 | 至少补一样真的：`content` / `art` / `client` / `notices` / `routes` / 素材之一 |
| 明明有图，包被拒了 | 有 `assets/` 文件夹却**没写 `license`** | 加一行 `"license": "CC-BY-4.0"` |
| 文件夹名和 `"id"` 不一致，包消失了 | 引擎按 `<workshop 文件夹>/<包 id>/pack.json` 找包，名字对不上就**整包跳过** | 让文件夹名 = `pack.json` 的 `"id"` |
| 两个包都加了同一个干员，先装的那个没了 | 两个包抢同一个 id：**包 id 字典序小的赢**，而且与扫描顺序无关 | 改包名，或者让其中一个包别放这条 |
| 提交后报「官方 id 撞车」 | 改**官方已有**的记录，必须在 `pack.json` 的 `overrides` 里显式声明 `"chess:<id>"` | 加 `"overrides": ["chess:chess_char_3_01_a"]` |
| 覆盖只改了一个数值，这个干员整个崩了 | 覆盖是**按字段打补丁**，但**行为和结构字段整块替换**（`skill` / `talents` / `rangeGrid` / `modules` / `bonds`…） | 想连行为一起接管，就必须成套补回 |
| 往记录里加了一个新字段，整条被拒 | 覆盖是**封闭世界**：写了记录里没有的字段就会被拒 | 要发明新字段，就把它做成一个**新 id 的新记录** |
| `"combat": false`，但包里的东西完全不生效 | 能改对局结果却标 `false` ⇒ 直接拒 | 改成 `"combat": true`，并在包说明里写明「会影响对局结果」 |
| 引擎升级后，以前能用的包突然装不上了 | `api` 是**会强制比对**的版本区间。引擎抬到 2 时，写 `"1.x"` 的包被拒 | 改 `api` 区间。这是**保护**，不是 bug |
| `api` 写成数字 `1`，包看着没问题但区间不生效 | 类型闸门直接拒非字符串的 `api` | 加引号：`"api": ">=1 <2"` |
| 包的格式完全正确，却被整包拒绝，理由列了 38 个字段 | `pack.json` 的顶层字段是**闭集**，写了不认识的键就被拒 —— 刻意不静默 | 删掉那个键，或换成合法字段 |
| 想让包覆盖引擎自己的文件（`data/**`、`server/sim/**`） | **刻意没有这条路** | 这类能力得先在引擎里做成开关，包才能声明 |
| 技能文字写得好好的，游戏里一点效果都没有 | 技能里的键用了引擎不认的写法 —— 不报错，也不生效 | 看校验器给的警告，要么换成清单里的键，要么改成写代码那条路 |
| 新干员画成一张菱形贴纸 | 模型 id 填了一个不存在的 | 从 `data/assets.json` 里挑一个真实存在的；第一版建议只换立绘，别碰模型 |
| 干员的职业加成全部失效，但没报错 | 职业名写成了通用名（`DEFENDER` / `VANGUARD` / `SPECIALIST`） | 本项目用的是 `TANK` / `PIONEER` / `SPECIAL`，照引擎文档那张表写 |
| 手工压的 zip 上传被拒 | 上传站只认 zip 根，手工压缩常把整个文件夹压进去 | 用 `node tools/workshop-pack.mjs export` 导出，**别手工右键压缩** |
| 改完包，游戏里没变化 | 引擎**没有热重载** | 重启游戏服务器；编辑器里点「启动试玩」也会替你重启 |
| 照抄文档里的代码块，`pack.json` 解析失败 | 老文档里有用 ` ```jsonc ` 写的**带 `//` 注释**的示例 —— JSON 不允许注释 | 照抄时把 `//` 那一段删掉；本文的模板是**纯 JSON、原样可存** |
| 校验说「有 1 条错误」，可游戏里包明明在 | 「有错误」和「没装上」是**两件事**：声明了文件却找不到时，引擎仍然算这个包装上了（实测 `packs=1 errors=1`） | 看错误具体是哪一条再决定改不改；界面里「校验这个包」会把这两种状态分开显示 |

## 附录 D · 这一层写过的三件事，现在的状态

**源码仓库那三份老文档（`README.md` / `SKILL.md` / `UPLOAD.md`）已经按引擎 0.3.0 重写过一轮**：
下面 ① 已经补上，**② 与 ③ 仍然成立**。在入门层一律以本节为准。

**① zip 套不套顶层目录 —— 现在写明了是「两个落点两套形状」。**
本地安装 / 仓库收录要 `<包 id>/pack.json`（套一个顶层目录，目录名就用包 id）；**上传站只认 zip 根**里的
`pack.json`，套了顶层目录即 400 拒收。对照表见源码仓库 `SKILL.md` §3。
**实测反证**：官方导出命令 `workshop-pack.mjs export` **产出的就是扁平 zip**（实测：`pack.json` 直接在根，2 个文件共 575 字节）。
⇒ **导出用官方工具，上传用导出产物；不要手工重压。** 本文第 3 步为准。

**② 有的示例代码块照抄会坏。**
`SKILL.md` 里还有 ` ```jsonc ` 的示例（例如 §5.2 的 `{ "api": ">=1 <2" }   // ✅ 对`）—— 一个代码块里**两个** JSON 对象，还带 `//` 注释。
**JSON 不允许注释**，照抄进 `pack.json` 会解析失败，而错误信息不会指向「你抄错了文档」。
⇒ **本文第 1 步那段 `pack.json` 是纯 JSON，原样可存。**

**③ `license` 到底什么时候是硬要求。**
老文档只说「`license` 不能省」，但真实判据是**有条件的**：
`shared/workshop.js` 那一处是 `if (opts.hasAssets === true && !license)` ——
**只有包里存在 `assets/` 文件夹时才强制**。所以「最小可装包」没有 `assets/` 也没有 `license`，它跑得通。
⇒ **一句话：带图（有 `assets/`）= 必须写 `license`；纯数据包不强制。**
换立绘一定要有 `assets/`，所以**换立绘 100% 需要 `license`**。

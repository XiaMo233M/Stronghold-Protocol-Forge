## 0.5.0 — 2026-10-07

四件事：**盟约（羁绊）终于能被完整编辑**、**助战干员进商店**、两处「没有任何报错」的静默失败被堵住。

### 盟约编辑器（新的第六页 `/bond.html`）

盟约在引擎里分成三层，这一页按三层画，因为「改了就生效」只在其中两层成立：

- **覆盖官方 23 条 = 真正修改盟约**：官方效果在引擎里按 id 写死，但它的阈值、计数模式、说明、黑板数值全部从
  `data/bonds.json` 的记录读。所以把官方 id 存进工坊包（自动写 `pack.json` 的 `overrides: ["bonds:<id>"]`），
  改一个阈值或一个 `bb` 数字立刻生效 —— 实测 `yanShip` 的阈值 3/6/9 改成 2/3、`base_atk` 0.23 改成 0.5，
  合并后的数据与官方处理器读到的都是新值。
- **新增盟约在战斗里也能加东西**：官方那 23 条之外的盟约原本只有数据面。现在记录里写 `"genericBuffs": true`，
  `server/sim/content/bonds/dataDriven.js` 就按 `bb` 的 `base_atk` / `atk_per_stack`（防御、生命上限同理）
  给成员加百分比，与官方盟约同一个「直接乘算」桶（相加，不是相乘）。用记录上的开关而不是「不在官方 23 条里就
  自动生效」是刻意的：后者会把**覆盖**官方盟约的黑板叠加两次，而双倍加成不会报错，只会让平衡悄悄歪掉。
- **成员不是盟约自己说了算**：`members` 由干员的 `bonds` 列表推导（引擎按干员记录数人、盟约弹窗列的也是它）。
  成员那一段勾选等于去改那些干员的 spec —— 只有本包自有的干员能改，改不动的会明说「先把它覆盖进本包」。
- 表单覆盖：身份（id/名称/顺序/权重/核心/类型/图标）、计数与阈值（阈值、计数模式、阈值模板、生效范围、
  最大层数、整备区计数、只数精锐）、说明与效果、战斗黑板（六个通用键 + 任意自定义键）、成员。
- 覆盖官方时页面顶上有一条红字提醒「不要打开通用加成」；右侧预览直接给出「战斗里会加：攻击力 +20% +2%/层」
  或「不会加任何东西」的结论 —— 这一层最容易「看起来做了但没生效」。
- 图标说清了只能复用本机已装好的（客户端按**盟约 id** 取图，一个包无法给 `assets.json` 加条目）：新增盟约在
  盟约条上是一个圆点，覆盖官方则沿用官方图标。

### 助战干员进商店（按业主的口径）

业主定的规则：**「助战干员就应该加入商店，按阶级像普通棋子一样购买出售」**。所以不再开局白送：

- 选为助战的干员在共享池里**多一份拷贝**（`cap` 与 `left` 同时 +1，共享池恒等式仍然成立），于是它像普通棋子
  一样被摇到、按阶级价买到、按普通规则卖掉。阶级门照旧（六阶助战仍要店铺等级 6）。
- **本局随机禁用的干员，作为助战照样进池**：「禁用抽卡」不是「禁用助战」，池中仍保留那一份助战拷贝。
- **价格可以改**：`data/support.json` 新增 `prices: { "<chessId>": 3 }`（0–99 的整数，只认卡池里真有的 id），
  带上它的那名玩家在商店里按这个价买；没配的用它的阶级价；卖掉一律走普通棋子的 `sellPrice`。
  包管理页的助战表里直接就能改（留空 = 回到阶级价，取消助战时自动清掉那条价目）。
- 摇出来的助战格子带 `support: true`（`m.private` 里），客户端可以据此加个标。助战页的说明文字也一起改了。
- 机器人不带助战（席位上的 `support` 不再被当真）。

### 堵住两处静默失败

1. **工坊干员永远进不了商店**（业主报的「试玩时摇不到自定义干员」）：一个包可能是别的页面先建的
   （`content: ["stages"]`…），之后往里存干员时如果不给 `content` 补上 `chess`，加载器就**完全不读这个包的
   `chess.json`** —— 干员在编辑器里、在磁盘上、语法都没问题，却永远进不了游戏，而且没有任何报错。
   现在保存干员会自动补声明；包管理页还会额外点出任何「盘上有、`content` 没声明」的文件（手工编辑也躲不掉），
   CLI 的 `list` 同样会打印一行。
2. **干员没有模型 = 试玩里是一张头像贴图**：`assets.spine` 为空或填错时游戏不会报错，只会画一张头像菱形贴图，
   而编辑器此前允许这样保存、只给一条容易被忽略的警告。现在干员页当场判定并说清「会渲染成模型 / 是贴图」，
   保存时直接把没有模型的干员**拒绝**（外观下拉来自本机的模型清单 `/api/state.spineChoices`）；加载器那一层也会
   为手写包报出「这个干员没有模型」的警告（`[workshop] <包>: …renders as a flat portrait…`）。

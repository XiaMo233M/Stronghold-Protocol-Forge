## 0.12.1 — 2026-10-10

这一版补上中间层的**最后一大块载荷**：包可以写**整场的战斗逻辑**（`server.battle`，导出 `install(battle)`）—— 以前包
只有「一个干员一份 `kits/<干员id>.js`」这一条战斗入口，而一份真实 mod 的效果常常是整场的（「我方这个盟约的成员，对
处于眩晕/停顿/束缚/不动的敌人增伤」「凑够 6 名不同成员时全员加攻速、攻击额外带真实伤害」「两件装备同装时每秒对范围内
受控敌人造成伤害」）。上游游戏本体仍是 **0.2.2**，发行 tag：`v0.12.1-0.2.2`。

### 包写的**整场战斗逻辑**：`server.battle`

- 声明是 `server.battle = { module }`：包内 `.mjs`，导出 `install(battle)` —— 与官方内容模块（`content/bonds/*.js`）
  **逐字同形**。必须声明 `combat: true`，否则整包被拒（`BATTLE_NEEDS_COMBAT`）：改战斗结果的代码要进房间摘要闸门与
  golden 这条线。
- **import 面是白名单且两端都成立**：`@battle/index.js`（战斗内容层的辅助函数 —— 盟约 / 装备 / 特质的读法、
  `passiveBuff`、`directMods`、`battleStore` 等，官方内容模块用的同一份）与 `@sim/`（三个纯函数模块）。服务端把白名单
  说明符重写成真实路径后用 `data:` 模块加载，浏览器靠 `public/index.html` 的 import map 解同一批前缀 —— 所以包的源码
  **原样**在两端跑，服务端的复算与浏览器算的是同一段代码。
- 判据与 `server.meta` 一条线：源码在 import **之前**过静态确定性扫描（`Math.random` / `Date.now` / `fetch` /
  `setTimeout` / `process` / `globalThis` / `require` / `eval` 一律点名）；import 越界、模块文件不在、没有 `install`
  导出 ⇒ **整包**在同一个裁剪点移出已加载集合；模块字节进内容哈希；跑起来时**逐包** `try/catch` 隔离 —— 一个包抛异常
  只记一条内容错误，不让整个战场起不来。
- 两端通过 BattleSpec 的 `spec.workshopBattle`（与 `spec.workshopKits` 同形）对齐，浏览器从
  `/workshop-battle/<包>/<模块>` 取源码（只服务装载器登记过的 URL）。**房间声明了集合时只有它点名的包参与**，与数据 /
  kit / meta 同一条口径。

## 0.12.0 — 2026-10-10

这一版做的是**底层**：中间层（模组层）现在能同时装多种模组，而且**房间自己声明的那一套真的跑起来** —— 房主挑哪几个包，
那一局就跑哪几个包（数据、行为层、对局逻辑都只来自它们），客户端按房间取数据、进房间前先对齐本机持有；在此基础上包能写
**服务端对局逻辑**（`server.meta`）与**服务端模块**（`server.modules`），界面那侧能插进**既有组件**、读游戏数据、自带
样式表、按**引擎已定义**的消息类型收发，还能放一份**公告 / 鸣谢**。上游游戏本体仍是 **0.2.2**，发行 tag：
`v0.12.0-0.2.2`。

### 房间自己那一套真的跑起来（W-B / W-D）

- **声明了子集的房间，那一局只跑它声明的包**：数据、`kits/`、`server.meta` 处理器都按房间的集合物化（`server/roomAssets.js`，
  同一份集合摘要只物化一次、结果冻结）。**没声明集合的房间拿到的仍是进程级那一份本体**（对象身份，不是拷贝）——
  「不声明集合就与从前逐字节相同」因此是可断言的事实。
- **这一局的数据面按房间送**：`/room-data/<房间摘要>/<文件>.json`。只有**真的被房间声明过**的摘要会被回答（客户端编不出
  一个组合让服务器现场合并一份出来），文件名白名单与 `/data/` 同一份；`/data/*.json` 照旧是「官方 + 全部已装包」。
- **战斗模拟按房间取数据**：浏览器那一份按 BattleSpec 上的集合挑数据面，且按数据面各自缓存（一个页面先后进两个房间不会串）。
- **入座前的对齐门**：成员在点「准备就绪」之前，客户端用**本地字节**核对房间声明的每个包（文件缺了、字节被改坏、服务器
  根本没有这个包 —— 都算没对齐），缺的可以**就地补齐**（只下这个房间点名的包，进度就画在房间那一栏）；没对齐就不给准备
  按钮，所以房间不会带着一个跑不起来的成员开打。**旁观者不受这条限制**。入座门本身仍然只判进程摘要 —— 入座前客户端还
  不知道房间的集合，那一条证明的是「我们谈的是同一个包目录、同一批字节」。
- **两个旁路单例收口**：sim 里读盟约 / 道具 / 策略 / 特质的那条路过去直接读**进程级**那一份（等于读「全部已装包」），现在
  按**这一局**的数据走（构造与每一步都是同步区间内的一叠作用域，多局并发只会在步与步之间交错）；作用域外仍是进程那份
  本体，只带几张表的调用方不会把别的表读没。

### 包写的**服务端对局逻辑**：`server.meta`（社区 mod fanpack 的第一大缺口）

- 声明是 `server.meta = { module, registers }`：`module` 是包内 `.mjs`（服务端加载、浏览器永不加载），导出
  `registerMeta(registry)`（与官方内容模块**同形**）；`registers` 是这个包**允许注册的键的完整清单**（七类键，允许一个
  结尾 `*` 的前缀），没声明的键一注册就抛、整包在这一局回滚并点名。
- **必须声明 `combat: true`**，否则整包不加载并点名（`META_NEEDS_COMBAT`）：改对局结果的东西必须进摘要闸门与 golden 那条线。
- **按房间装配**（`MetaRegistry.fork()`），进程级那一份一个键都不动 —— 「开局前设全局、打完恢复」在多局并发时本来就是错的；
  两个包抢同一个键按包 id 升序定归属并点名。模块源码在 import **之前**过一遍静态确定性扫描（`Math.random` / `Date.now` /
  `process` / 爬出包的 `import` 全部点名）。装不上的包与 `server.preDispatch` 在**同一个裁剪点**整包移出已加载集合。
- 验收拿真实的社区 mod 逐句移植跑通：按层里程碑发奖那一段（一步只结一次账、发到手才算），以及「**6 名不同成员**」那段
  条件触发（摆 5 名不触发、第 6 名触发一次、第 7 名不再重复、精锐与普通算同一名成员）。

### 包写的**服务端模块**：`server.modules`

- 四个挂载点 `boot` / `shutdown` / `matchClass` / `healthz`（闭枚举，不开放任意挂载），`write: true` 才拿到限定在
  `<状态目录>/mod/<包id>/` 的 io 门面；`healthz` 回执限扁平标量（12 字段 / 2 KB）；挂 `matchClass` 的包必须声明
  `combat: true`。**两处有意的不对称**已写进文档：服务端模块是**进程级**（不是按房间），且只开这四个挂载点。

### C 层：插进既有组件、读数据、自带样式、收发引擎已有消息

- **宿主从四个浮层扩成九个**，新增 `screen.game.shopCard`（**可重复**：每张商店卡一个容器，面板用 `ctx.hostKey` 知道是
  哪一张）、`screen.game.bondStrip`、`screen.game.hud`、`screen.game.overlay`、`screen.loadout.detail` —— 「往商店卡加
  标记、给盟约条加手势、给 HUD 加角标、往干员调配详情插一节」都有挂载点，且宿主由引擎决定、包只选名字。
- **数据口** `ctx.data.get('<表>')`：只读**冻结快照**，白名单是浏览器本来就抓得到的那些表（没有 store 句柄、没有 fetch）。
- **样式两条路一起给**：`client.theme.vars`（CSS 自定义属性、加法语义、撤销时恢复）与 `client.panels[].styles[]`
  （包内 `.css`，只服务登记过的 URL、注入排在引擎样式之后、撤销时移除）—— 整份新组件的样式表装得下了。
- **消息额度**：`client.panels[].messages` 声明后可以收发**引擎已定义**的类型（线上唯一的 `pack.msg`，通道名由包定、
  类型名由引擎定、每会话限流、同房间转发）。包**不能**定义新的线上类型，`b.*` 永不在此列（C 扩展改不了对局结果）。

### 公告与鸣谢：`notices`

- 引擎那一半**从本文件生成**（单一事实源：更新记录写在哪、公告就是什么，不手写第二份），包那一半是
  `pack.json.notices = { announcement, credits }` 两份包内 `.json`；合并语义是**追加**（一个包的公告是它自己的新闻、署名
  是它自己的署名），合并体走既有的合并数据通道送到 `/data/notices.json`（没有新路由）。
- 客户端在登录页右上角有一个「公告」按钮；**链接只认 `https://`**（`javascript:` / `http:` 的网址丢掉但名字照旧展示）。

## 0.8.2 — 2026-10-08

这一版把上游基线从 **0.2.0 抬到 0.2.1**（含 0.2.1 的一批规则修复），并带上上游从这一版起的**增量更新包机制**。发行 tag：`v0.8.2-0.2.1`。

### 上游 0.2.1 照收的内容

**规则**（都按官方数据与 PRTS 核对，细节见 [docs/history/0.2.1.md](docs/history/0.2.1.md)）：

- **联防改回在本回合的战场上进行**：地形、水池、箱子与装置和官方一样保留，两名支援者分站左右两个半场。0.2.0 换上的「空马路」其实是所有波次模板共用的占位地图，现在撤回（0.2.0 的其它联防修正全部保留，GitHub #244）。
- **突袭可以跳到队友的半场**了，但只限两边都有人的战场；单人支援的联防与独自一人的领袖战场仍只跳自己那一半，也不会落到手牌 / 临时整备区那两排。
- **干员按满潜能计算**（含精锐与自选干员）：部署费用、再部署、攻击 / 生命 / 防御 / 法抗 / 攻速，以及「天赋效果增强」；召唤物的天赋也按召唤者的满潜能取值，但不继承其属性加成。一阶刺玫（E1 Lv55）因此从攻击 **413**、费用 **17** 变为攻击 **435**、费用 **15** —— 正好是她的潜能「攻击力 +22」「费用 −2」。
- **装备栏满时再装一次性道具会弹「替换装备」窗**：先销毁你选中的那件再触发效果，干员留下一个空栏位（官方规则）。
- 凋亡爆发期间每秒损失的技力**连同已存充能一起扣**；「频次」器物（瑞印 / 卷轴 / 铜镜 / 镇纸 / 茶器 / 矛头 / 灯盘等 14 种）的所需击打次数随难度与回合的敌人生命加成变化，领袖在战斗中召唤的单位也吃当回合加成。
- 拉普兰德：贾维策略在第 6 次刷新送来的那位，不会在送来的这次刷新里就叠【叙拉古】层数。

**界面**：局内盟约栏的收起按钮改成半透明小箭头；盟约详情的成员列表会列出**你的自选干员**（含未买到时的灰显与红色 ✕，观看队友时点他的自选干员能打开详情卡）；**飞行敌人飞过高台不再一高一低像走楼梯**（高度从路面算起、固定离地约 1.3 格）；巨大的丑东西与自在的重生 / 晕眩动画、猎狗pro与深池侦察犬的跑步动画补全；策略「Touch」的详情卡按干员卡显示特性 / 技能 / 天赋；「自选编队」的选择干员窗口按 Esc 只关闭这个窗口。

**联机**：浏览器还在加载战斗模块、或正在静默追赶战场进度时，服务器发来的**接管与强制结束不再丢失**（战斗建好后按收到的顺序生效）。

### 更新包机制（0.8.2 起每个版本都提供）

- 发行页除完整包 / 配音包 / 源码包外，多一个 **`…-update.zip`**：只含比上一版改动过的文件 + 要删除的旧文件清单。停止游戏、解压覆盖到安装目录、照常启动即可。
- 启动时服务端先按 **`MANIFEST.json`**（每个程序文件的大小与 sha256）校验：不一致就提示去下完整包、**不带着半个坏包启动**；校验通过才应用更新、删掉新版本不再需要的旧文件。**你自己改过的文件不会被删**（只删「旧版本原样、新版本已移除」的那些）。
- `npm run doctor` 多了一行「文件校验」，随时能看到程序文件是否与这个版本一致。
- 维护者侧：`tools/package-update.mjs` 从两个整合包生成增量包（`tools/package.mjs --update --from <上一版 zip>`）。

### 修掉的真 bug

- **中文文件名的 zip 会被更新机制读错**：`tar` 在 Windows 上写 zip 条目名用的是本地代码页（CP936），而 zip 里那个「这个文件名是 UTF-8」的标志位没设；上游的 zip 读取器只按 UTF-8 解码，于是我们**自己发行的包里** `启动游戏.bat`、`README-开箱即用.md`、`安装工坊包.bat`、`启动编辑器.bat` 四个名字全成了乱码。按它生成的增量更新会把同一个文件当成两条不同路径（一条乱码、一条真名）发下去。现在读取器按规范先看标志位、没设时严格试 UTF-8、再退回系统代码页（Windows 用 GBK）—— 与玩家自己解压时看到的名字一致；实测 0.8.1 的发行包现在解析出 `README-开箱即用.md` / `启动游戏.bat` / `启动编辑器.bat` / `安装工坊包.bat`。
- 编辑器新建包时写进 `pack.json` 的 `gameVersion` 一直写着 `0.1.3`（0.2.0 移植后没跟着更新），现在写 `0.2.1`。

## 0.8.1 — 2026-10-08

这一版的主线是**把「不许手改 `pack.json`」这条规矩补完**：`pack.json` 里最后两块只能手写的东西 —— 元数据与
`overrides` —— 终于有了图形入口，其中 **`license` 是会挡住其它页面的那一个**。另外补上 0.8.0 只做了一半的
**召唤物外观**（`art.tokens`），并关掉 0.8.0 说明里自己列出的两条「已知边界」。

### 包元数据与 `overrides` 有了图形入口（此前只能手改 `pack.json`）

`pack.json` 的 `name` / `version` / `author` / `license` / `description` / `gameVersion` 此前只有一个创建时的
默认值，之后**只能手改**。这在一个地方会真的把人挡住：

> 一个包只要有 `assets/`（语音、装备图标、外观素材都要它），`pack.json` 就必须声明 `license`，否则**整个包**被
> 加载器拒绝（`ASSETS_NEED_LICENSE`），而语音页、装备页、外观素材三个写入端点在这种状态下**一律拒绝写入**
> —— 页面却只能告诉作者「去 `pack.json` 里声明一个」。

现在包管理页有一块**包元数据**（`POST /api/packs/:id/meta`，实现在 `tools/workshop-pack.mjs` 的 `writePackMeta`）：
六个字段各一个输入框，`license` 带候选也可以手填；缺 `license` 的包在这一块顶部有一条明显的横幅（语音页那条
警告也改成指向这里）。写入规则与 `support` 一致：**只动传进来的键**，其余字段与键序原样保留、新键追加在末尾、
内容没变就一个字节都不写。`null` / 空串 = **删掉那个键**（加载器对它们各有默认值：`name` 退回包 id、
`version` 退回 `0.0.0`，其余就是「没声明」），页面写明了这一点。

唯一被拒绝的清空是 **license**：一个有 `assets/` 的包把它清空会被当场拒（400 `ASSETS_NEED_LICENSE`），因为那只会
写出一个整包被拒的包；其它字段照写 —— 一个还没填 `license` 的包不该连名字都改不了。`id` 不可改（它必须等于
目录名，改它等于换一个包）。

**`overrides`（覆盖官方记录的声明）** 同样有了入口（`POST /api/packs/:id/overrides`）。包带了一条 id 与官方相同
的记录时，只有声明了 `"<文件>:<id>"`，加载器才会用包的那条替换官方的；**没声明的冲突会被整条丢掉，而且一条
日志都不打**。除盟约页会自动写 `bonds:<id>` 之外，此前只能手写。

- 候选就是**官方每张表的 id + 名字**（13 张表约 1400 条）：作者通常知道要覆盖哪一个，但 id 是
  `chess_char_1_01_a` 这种记不住的形状，所以下拉里带官方名字；**也可以手输**（候选是提示，不是白名单）。
- 每条声明标出两件事，**两者都不是错误**：**在用**（本包真的带了这条 id 的记录，声明才会生效）与
  **官方有没有这个 id**（官方没有的话这条声明永远不起作用）。
- **删除永远不被「有没有在用」挡住**：加一条、删一条都是把新表发回来；形状由 `OVERRIDE_ENTRY_RE` 判（与加载器
  同一份正则），官方没有的 id 照收 —— 写进去的东西必须能在界面上删掉。

### 召唤物外观（`art.tokens`）

0.8.0 做了 `chars`（干员）与 `enemies`（怪物）两张表，召唤物那张表当时**没有界面入口**。现在干员页的外观段里
多了第三块：给这一页的干员召唤出来的东西配头像 / 立绘 / 模型。

- token id 的候选来自服务端新增的 `tokenChoices`（官方 `tokens.json` 的键 ∪ 官方与各包 `chess.json` 里引用过的
  id ∪ 各包 `tokens.json` 的键，带名字），**也可以手输** —— 新召唤物在写进 `pack.json` 之前不可能出现在任何候选里。
- 与另外两张表同一个做法：只列本包 `assets/` 里真实存在的素材、**选完 `.skel` 自动填同目录同名的 `.atlas`**、
  动画名从骨架里真实存在的名字里选、整条一次保存；下面还有一块「**本包已声明的**召唤物」清单（含陈旧条目）逐条可删。
- 这一块**与干员自己的 `assetsSpine` 无关**，所以没填 spine 的干员照样能配（挂在那条提前返回之后等于把
  「加一条 `art.tokens`」系在了另一张表的字段上 —— 删得掉、加不了正是这一版要消除的）。

### 已声明条目清单不再随当前编辑对象消失

装备页那块「本包已声明的装备图标」以前只在**打开一件装备**时出现。于是最需要它的时刻反而看不到它：一个包把
最后一件装备删掉之后 `items.json` 是空的，那条陈旧的图标声明又回到「只能手改 `pack.json`」。现在它**在没有打开
任何装备时也照样在**，包跟右栏「保存到」那个下拉同一个来源；一个包都还没有时，这一段会就地给一个包选择器。
判定「有没有人在用」抽成了唯一实现（`iconIdsInUse()`），有 / 无 spec 两条路径共用。

### 对齐：解析不出来的骨架不再是「只警告」

外观素材的 `.skel` / `.atlas` **解析不出来**时（字节根本不是 3.8 骨架）编辑器此前只给一条警告、照旧放行，而
命令行校验器对同一件事报 `ART_SPINE_VERSION` / error —— 两边不一致意味着作者会得到一个「编辑器让你存了、命令行
说你错了」的包，而客户端两边都只是**静默**不画。现在编辑器也拒绝（`artSkelInfo` / `artAtlasInfo` 的 `kind` 区分
「我们没解析」与「解析了但坏了」）。唯一仍然只是警告的是「超过编辑器自己的 8 MB 解析上限」：那只是我们没去读，
骨架本身可能是好的，动画名可以手填。

## 0.8.0 — 2026-10-08

这一版四件事：**工坊包能自带外观素材**（包新增的干员/怪物不再是「一张菱形贴图」）、**编辑器里再也没有浏览器原生对话框**、
**「写进 `pack.json` 的东西必须在界面上看得见、删得掉」**（业主的硬约束），以及一批真 bug 的修复。

### 工坊包自带外观素材（`pack.json.art`）

客户端画单位时，模型与头像都从合并后的 `data/assets.json` 取，而包加不了条目 —— 所以新干员只能复用官方已装好的模型 id，
否则就是一张菱形贴图（启动日志里那条「这个干员没有模型」的警告说的就是这件事）。现在包可以把素材放进自己的 `assets/`：

```json
"art": {
  "chars":   { "char_ws_my_op": { "avatar": "art/a.png", "portrait": "art/p.png",
               "spine": { "front": { "skel": "art/op.skel", "atlas": "art/op.atlas", "anims": { "idle": "Idle" } } } } },
  "enemies": { "enemy_ws_thing": { "icon": "art/i.png", "spine": { "skel": "…", "atlas": "…" } } },
  "tokens":  { "token_ws_thing": { "avatar": "art/t.png", "owner": "char_ws_my_op" } }
}
```

- 形状与官方条目 **1:1**（`chars` 的 spine 是嵌套的 `front`/`back`，`enemies`/`tokens` 扁平），照官方条目抄就行。
- 并进 `assets.chars` / `assets.enemies` / `assets.tokens`（`workshopArtIndex` / `mergeWorkshopArt`），**字段级合并**：
  包只给头像时官方模型照旧；只给 `spine.front` 的 `skel`/`atlas` 时，官方那一侧的 `anims`/`events` **留着**。
- **客户端零改动**（`validSpine` 只要求 skel 是 `/` 开头的路径）。包把模型接上之后，启动日志里那条「没有模型」的警告
  **自动消失**（合并顺序要在 `chessLookIssues` 之前，这一点有测试钉住）。
- 两条包改不了的硬约束，编辑器保存前就挡住：**`.atlas` 必须与 `.skel` 同目录同名**（加载器是从 skel 路径推 atlas 的，
  清单里那个字段只用于内存回收）、**`.atlas` 里写的每一页 png 必须与它同目录同名**。`.skel` 只放行 **3.8.x**。
- 编辑器干员页「外观」段与怪物页「美术」段各多一块：文件从本包真实素材里挑、**选完 skel 自动填同名 atlas**、
  `anims` 按角色给出**骨架里真实存在的动画名**下拉（服务端用客户端同一个解析器读）、`textures`/`pma` 保存前自动补。
- 作者侧校验新增一层体检（11 条 code）：文件缺失、类型不可服务、atlas 不同名、图谱页 png 缺失、缺 `size:`、
  版本不是 3.8、缺 `anims`（新 id 是 error、覆盖官方 id 是 warning）、动画名不存在、`pma` 不一致、id 没人用 ——
  **客户端在以上情况一条日志都不打**，所以这一层是这条通道的安全网。

### 编辑器：原生 `prompt()` 全部换成页内表单

7 处（6 处问工坊包 id + kit 页那处手写下拉）全部删除。`packPicker.js` 的「＋ 新建一个包…」现在**在下拉原地展开输入框**
（自动聚焦、Enter 确认、Esc 取消），空值 / 形状不对 / 重名就地报错，校验规则与加载器同一套；随之产生的 i18n 死键同步清掉
（那份词典是双向校验的）。**包仍然由第一次保存创建**，确认只是换掉当前保存目标。

### 不许手改 `pack.json`：已声明的东西全都看得见、删得掉

- 装备页、盟约页各多一块「**本包已声明的图标**」清单：列 `pack.json` 里**全部**声明（含陈旧条目），标出
  「有人在用 / 陈旧没人用」，每条都能直接删。以前只有当前正在编辑的那件装备/那条盟约能看到 —— 改掉一个 `trapId`
  之后旧声明就只剩手改清单这一条路。
- 外观素材同样有「本包已声明的**外观**」清单，同一条规矩。
- 服务端跟着补了一处顺序错误：**盟约图标**的清空请求此前会先被「本包的 `bonds.json` 里没有这条盟约」拒掉，于是陈旧
  声明在页面上看得见、点删除却 400。现在存在性检查只留给**配图**，清空永远放行（装备图标与 art 端点一直是这个顺序）。

### 修掉的真 bug

## 0.10.0 — 2026-10-09

这一版把上游基线从 **0.2.1 抬到 0.2.2**：**全量对齐**，一行不改地上游对局层与规则层的所有变化。发行 tag：`v0.10.0-0.2.2`。

### 上游 0.2.2 照收的内容

**规则**（都按官方数据与 PRTS 核对，细节见 [docs/history/0.2.2.md](docs/history/0.2.2.md)）：

- **潜能与练度改成按干员、按玩家在运行时输入**：干员调配里每名干员（普通 / 精锐 / 自选共用）可以设潜能 1–6 和练度，缺省**满潜 + 精英阶段2-60级**；旧调配存档照读，没设的按缺省。因为缺省带满潜与自持有加成，持有干员的攻击 / 防御 / 生命上限比 0.2.1（一律满潜、没有自持有加成）**高约 10 %**。数据层是**记录里的满潜现值 + 潜能注解**：每条记录带 `potDown`（各档要改的叶值）和链式天赋 `potMin` + `potBelow`，引擎按设置逐档还原；`room.loadout.ops` 携带每名干员的设置。
- **协议口径收紧**（`PROTOCOL_VERSION` **仍为 1**）：新增 `room.loadout.ops`（每名干员的潜能 / 练度设置）；`b.progress` 新增可选的 `resolved`（顶栏胶囊的分子：本战场**自己排定**的敌人里被打死或漏掉的，分裂与召唤不计；客户端不报时队友界面退回 `killed`）；`b.progress` 新增 `leaksBy`（每名玩家漏怪各自扣的 LP，`leaks` 减去它之和才是领袖自己的扣血效果）；`unitStatsEntry` 新增 `dir`（详情卡按朝向画攻击范围）；校验里**去掉 `killed <= total`**（分裂、召唤与部件不计数时 `killed` 可以超过 `total`）。语义变了而版本号没升 —— 所以**新旧客户端混用不会被版本检查挡住**，混用只会按各自的理解读这些字段。上游这么做是有意的（服务端自己发客户端，只有陈旧标签页会遇上，构建守卫会重载它），我们照收。
- **语音语言**：191 名有官方日配的干员、2674 条作战语音，清单里新增 `audio.voiceJp`（和中文同一套文件名，换目录）；设置里多一个「语音语言」中文 / 日本語。**主包只带清单里的默认配音（`audio.voiceLang` = 日文）**——0.7.2 起的规则，其余配音走 release 的语音包（`docs/WINDOWS.md` §2、§3）。四套配音的文件集这次**零增零减**，所以语音包不用重发。
- **统计页**（本机）：标题画面、大厅与等待室入口，胜率 / 策略通过率 / 称号 / 战斗累计 / 最近对局，只存在本机 `localStorage`（最多 1000 局、历史上限 80 万字符，最旧的先淘汰；只有最近 30 局保留行数据，更早的压成汇总行）；服务器**不存任何对局历史**。可以导出 / 导入，中途退出、没清完第一个回合的对局不计入。
- **界面**：点场上的装置（阻隔工事、双面箱、射击台、气流鼓风机等四类角色）会弹出**说明卡**，和点特殊地形的提示同款；详情卡里加**干员调配表**；打开详情卡时棋盘上画出该单位**当前的攻击范围**（按它现在的位置、朝向与技能）。
- 其余按官方数据与 PRTS 修正的规则（失衡、整帧攻击时序、领袖召唤的当回合加成等）与社区反馈的修复，逐条见 [docs/history/0.2.2.md](docs/history/0.2.2.md) §27。

### 中间层（mod 层）

这一版加了「让包能读写游戏底层」的中间层（设计见 [docs/design/mod-layer.md](docs/design/mod-layer.md)，作者向用法见 [docs/WORKSHOP.md](docs/WORKSHOP.md)）：三层口径 **A 内容层 / B 服务端逻辑层 / C 客户端界面层**。

- **身份与摘要**：每个包的字节算一个摘要，`/healthz`、`welcome` 与对局 spec 报**同一个**（`shared/modIdentity.js`，由 `test/modIdentityWire.test.js` 钉住）；进房时客户端要回显这个摘要，对不上会被拒并提示刷新 —— 一起进房的人必须用同一套模组，否则确定性模拟会发散。本版还没有「客户端选模组」的界面，包仍由服主装到服务器上。
- **归一「谁赢」与归因点名**：两个包改同一条记录时按固定规则裁决，冲突点名到包 id。
- **覆盖模式**：`pack.json.overrides` 按**字段**打补丁（不是整条替换），闭合世界 —— 写了记录里没有的字段整条拒绝；编辑器放行对官方 id 的覆盖。
- **干员包通道**：新增 `units` 内容文件与 `pack.json.operators` 自选池声明（四条点名拒绝：无记录 / 非 6 星 / 盟约未知 / 形态缺档），并支持两张扁平图标表（技能图标 / 分支图标）。
- **kit 受限 import**：白名单文件 + 导出名下限守卫，服务端窄重写与浏览器 import map 双端解析。
- **试玩开关搬到行为层**：`pack.json.playtest.directToHand`（写在记录里的开关在覆盖官方干员时会被摘掉而静默失效）。
- 新增第三方 mod 的**接口面守卫测试**：把就地补丁依赖的接口钉成断言。
- **刻意不做**的部分（B 层无沙箱、无热重载、无代码签名与作者身份等）逐条写在设计稿 §28.11。

### golden 基线：会改变对局结果（这次与以往不同）

六个语料（`test/golden/*.json`）里**只有 `matches` 移动**，且 **18 / 18 场全部归因**到上游 v0.2.2 本身的对局层变化：`roster` / `bonds` / `fields` / `standins` / `diy` 五个家族**重算后与旧基线逐字节相同**（⇒ 0.2.2 **没有碰战斗内核**），`matches` **18 场里 17 场与上游 v0.2.2 逐字节相同**。

唯一与上游不同的是 **`coop2-NORMAL-14-standins`**：补位（stand-in）候选池我们排除 12 位、上游排除 9 位 —— 这是 0.2.0 移植时就定下的**刻意分歧**，不是本次移植引入的偏差。

**这条要写进更新记录的理由**：0.8.2 那次 matches 的差异全部来自我们自己的分歧，与上游对局结果无关；这次不同 —— **上游 0.2.2 的对局层变化会实际改变一局怎么走**（含结局翻转：`solo-HARD-1` defeat r=13 → victory r=14、`solo-HARD-2` eliminated r=12 → defeat r=13、`solo-ABYSS-1/2` 各多推一回合）。对玩家是「同一套输入会打出不同结局」，对我们则是移植正确性的实证：我们与上游同步，而不是自己漂移。

### 我们自己的分歧与修复照旧保留

- **刻意的分歧**：调度中心升级只多一个空位（0.7.2 起，上游 0.2.2 已在自己的实现里收敛）、助战干员进商店的定价（0.5.0 起）、补位候选池的排除名单（0.2.0 起，即上面那唯一一处 matches 差异）。
- **我们的修复**：3D 预览的滚轮缩放改对参数（0.9.3，拉的是 `scale` 不是 `dist`）、「显示寻路」那一层缺数据（0.9.4，编辑器按开关请求 `paths`）—— 两者都是编辑器侧，上游没有对应实现。

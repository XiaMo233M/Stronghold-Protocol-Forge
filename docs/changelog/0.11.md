## 0.11.1 — 2026-10-10

这一版只修**导入工坊包**这一条路：包里带**中文（或其它非 ASCII）目录名**时，过去会被判成**坏包**拒收。上游游戏本体仍是 **0.2.2**，发行 tag：`v0.11.1-0.2.2`。

### 修好「带中文目录名的包导不进来」

`shared/zip.js` 过去拿**严格 UTF-8** 解**每一个**条目名，解不开就整包拒（`ZIP_BAD_NAME`）—— 而 Windows 的 `tar`
与资源管理器写中文名用的是**本地码页（GBK）**，而且**常常不置** ZIP 的「UTF-8 名字」标志位（bit 11），于是一份
**结构完全正确**的包会被当成坏包。这个坑更新机制早就绕过（`tools/package-update.mjs` 自带一份解码器），工坊
导入成了漏网的那条路。

现在条目名的编码按 **ZIP 自己的规矩**分三种情况解，安全判据一个字没放松：

- **bit 11 置位**：头里承诺过这是 UTF-8，所以**只**认严格 UTF-8 —— 字节不合法就是坏归档，拒。
- **未置位**：先认 **Info-ZIP Unicode Path extra field（0x7075）**，并**校验它与头里名字的 CRC**（对不上就不用它）。
- **再没有**：严格 UTF-8 → 严格 **GBK**，两种都解不出来才拒（例如真坏的 `0xFF`）。

解出来的名字照旧过同一条安全规则：**路径穿越 / 绝对路径 / 反斜杠 / 空段**一律拒。**本地头与中央目录的名字**
也按同一套规则解出来再比对，所以中文目录名的包不会再被误报成「两处名字不一致」。

两份解码器（工坊导入、更新包）合并成 `shared/zip.js` 里的**一个**实现 `decodeEntryName`，以后只有一处要改。
端到端验过：GBK 目录名「资源」的包能被 `tools/workshop-pack.mjs import` 正常导入，落盘的文件名不坏。

## 0.11.0 — 2026-10-10

这一版把**中间层（模组层）从设计稿落成能力**：工坊包除了数据，现在还能声明**客户端资源容器**、**客户端面板**、
**分发前准入钩子**与**只读 HTTP 路由**，并新增给**已有语种**补词条的 `i18n`。上游游戏本体仍是 **0.2.2**，
发行 tag：`v0.11.0-0.2.2`。

### 包能做的事多了五组（DESIGN §28.13）

- **`assets`**：包自带**资源容器**（`.spresources`）与**扁平清单**；两者经 `/workshop-resources/<包>/<路径>`
  送出（容器**流式**送，不整读进内存），装载期按旁挂 `.sha256` 把容器哈希一遍，**摘要对不上或没有摘要就整包不加载**。
  `serverPolicy: "cache-only"` 让服务器对 `/assets`、`/fonts` 回 412 且**不回源**（进程级，启动日志点名是哪个包声明的）。
- **`client.panels[]`**：包自带的界面模块经 `/workshop-panels/<包>/<模块>.js` 送到浏览器，按 `slot` / `order` /
  `gate` 挂到四个宿主；注入面冻结（没有 store、没有 match、没有 battle）。
- **`server.preDispatch`**：包声明的**分发前准入钩子**，插在 `validateC2S` 之后、`hello` 之前。注入面恰好**八个键**
  （`pack` / `policy` / `policyFile` / `intercepts` / `c2s` / `log` / `now` / `send`）—— 没有 socket、没有对局对象，
  所以钩子**改不了对局结果**。三个 `resource.*` 的 `C2S` 类型随之落地（`PROTOCOL_VERSION` **仍为 1**：老客户端不发它们）。
- **`routes[]`**：包声明的**只读** JSON 路由（只 GET / HEAD，只 `.json`，只精确路径，不做重写）。
- **`i18n`**：给 `en` / `ja` / `ko` / `zh-TW` 这类**已存在**的语种补界面词条；**已有键绝不覆盖**，冲突逐条点名，
  官方语言文件一个字节都不改写。
- **顶层键改成闭集**：`pack.json` 里写一个这份格式不认识的键（`variants` / `skins` / 拼错的键），现在
  **点名拒绝整个包**（`PACK_UNKNOWN_FIELD`），不再静默丢掉 —— 「写了等于没写」是这一版修掉的主要失败模式。
- **一条用不了的声明拒绝整个包**：`client.panels` / `server.preDispatch` / `assets` / `i18n` 声明了却用不上
  （文件不在、形状不对、模块装不上），**整包不加载**并点名理由，而不是「包照旧加载、那个能力没生效」。

### Service Worker 的口径（业主裁决 2026-10-10）

根作用域的 SW 能拦截该站点**所有**请求，所以它**由引擎自带**（`public/resource-sw.js` + `public/js/resources/**`），
包**只声明** `assets`，没有任何字段能指定一个 SW 地址。没有包声明 `assets` 时：不多一个请求、不多一个 DOM、
不在 `globalThis` 上留任何名字。

### 修好「装了模组的服务器上浏览器进不去房间」

房间现在可以声明**自己的**模组集合（`room.create` 的 `modIds`，只能点本服务器**已经加载**的包；点一个不存在的包
会被**点名拒绝**，`ERR.MOD_UNKNOWN`），`room.state.mods` 把这份集合发给成员与旁观者；**没有声明集合的房间帧与从前
逐字节相同**。客户端的摘要回显同时修好了原来那个「装了模组的服务器上进不去房间」的问题。

### 客户端 mod 本地缓存（接口层）

新增 `/mods/catalog.json`（本机装了哪些包、各有哪些文件）与 `/mods/file/<包>/<路径>`（按目录清单取文件，只服务
清单里列过的路径），以及**可注入存储**、**带完整性校验**的下载器。本版只到接口与纯逻辑：**界面与「按房间集合算缺件」
在下一个小版本**。目录由**裁剪后**的已加载集合构建 —— 声明了闸门却装不上钩子的包不会出现在目录里。

### 工具与文档

- **作者侧校验器判的是合并后的记录**：一份**覆盖官方记录**的差量补丁过去会被当成一条完整记录判，一份合法的社区
  内容包实测拿到 **184 个 error**；现在对 `pack.json.overrides` 里声明过的 id 判 `loadData` 的**合并体**
  （与引擎、编辑器同一份判据，「编辑器接受什么、校验器就接受什么」）。
- **钩子模块可以导出 `validatePolicy(policy)`**：策略文件的**内部形状**是钩子自己的方言，装载器判不了；模块说
  「不能用」就按 `PREDISPATCH_BAD_POLICY` 把**整包**移出已加载集合，与「策略不是 JSON 对象」同一个结局。
- 文档改准两处会误导作者的写法：`client.panels[].gate` **不能**用来等**自己**会置真的标志（照抄会让那个面板永远
  挂不上）；`serverPolicy` 只管**服务端**，而资源 SW 的 412 与它无关。
- 引擎侧记录：设计 [docs/design/mod-layer.md](docs/design/mod-layer.md) §28、作者向 [docs/WORKSHOP.md](docs/WORKSHOP.md) §1.9 / §1.10。

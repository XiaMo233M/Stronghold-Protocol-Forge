## 0.7.3 — 2026-10-08

这一版把**包内多语言配音**补齐 —— 0.7.1 把玩家侧的多语言配音做完了，但工坊包当时只能往默认配音那一档加台词，
「包内给某干员单独配一种语言」是明说的遗留项。同时给作者手册补了一份「常见效果怎么做」。

### 工坊包可以按语言配音（`pack.json.voiceLangs`）

一个包现在能给同一个干员配多种语言的台词：

```json
{
  "content": [],
  "voices":     { "char_ws_my_op": { "select": ["voice/cn_select.mp3"] } },
  "voiceLangs": { "jp": { "char_ws_my_op": { "select": ["voice/jp_select.mp3"], "place": ["voice/jp_place.mp3"] } } }
}
```

- **形状与 `voices` 逐字相同**（同一份 `parseVoiceTable`）：槽位词表、干员 id、路径安全规则、去重与排序全部共用，
  错误码也共用（`VOICE_SLOT_UNKNOWN` / `VOICE_PATH_UNSAFE` / `VOICE_BAD_CHAR_ID` / `VOICE_EMPTY`），
  只是提示里会带上具体是哪张表（`voiceLangs["jp"]["char_ws_my_op"]["place"]`）。
- 语言键必须是 `shared/constants.js` 的 `VOICE_LANGS`（cn/jp/en/kr，否则 `VOICE_LANG_UNKNOWN`）；
  **默认语种不能写进 `voiceLangs`**（`VOICE_LANG_DEFAULT`）—— 默认配音就是 `voices` 本身，
  同一批台词有两个写法只会让作者猜不出客户端到底读哪一份。空语种表是 `VOICE_LANG_EMPTY`。
- **只带 `voiceLangs` 的包**（`content: []`、一条默认配音都没有）是合法的包：这个包只补某个语种。
- 送达：默认配音并进 `assets.audio.voice`，其它语种并进 `assets.audio.voiceLangs[<lang>]`
  （`shared/workshop.js` 的 `workshopVoiceLangIndex` / `mergeWorkshopVoices`）—— 正是客户端
  `public/js/audio.js voiceLinesFor` 按玩家设置查的那两张表，所以**播放侧一行代码都没改**。该语种没有这个干员的
  条目时客户端照旧回退到默认配音那一档。只声明 `voices` 的包**不会**让清单长出一个空的 `voiceLangs`。
- 编辑器第七页 `/voice.html` 多了**语言选择**：默认配音 / jp / en / kr 各一张表，就地编辑、试听、保存，
  没声明过的语种不会被写出空表；作者侧校验 `tools/workshop-validate.mjs` 同样逐表检查（文件缺失、类型不可服务、
  干员不存在）。

### 工坊包自带装备图标（`pack.json.itemIcons`）

第三条「包自带素材」通道（前两条是语音与盟约图标），做法逐字照抄，理由也一样：客户端按**道具的图标 id** 从
`data/assets.json` 的 `items` 取图（`public/js/assets.js itemIconUrl`：先 `iconId`、再 `trapId`），而一个包没法往
`assets.json` 里加条目 —— 于是包新增的装备只能显示兜底图。

- `"itemIcons": { "<图标 id>": "<包内 assets/ 下的相对路径>" }`；校验规则与 `bondIcons` 同一套
  （`ITEM_ICON_BAD_SHAPE` / `_NEEDS_ASSETS` / `_BAD_ID` / `_PATH_UNSAFE`），**只带 `itemIcons` 的包也是合法的包**。
- 并进 `assets.items`（`workshopItemIconIndex` / `mergeWorkshopItemIcons`）：官方已有的 id **替换**、新 id 追加；
  两个包抢同一个 id 时按包 id 排序第一个赢并记一条错误；`assets.json` 本来没有 `items` 表时不凭空造一个（报告出来）。
- **客户端零改动** —— 它读的还是同一份合并后的 `assets.json`，图走 `/workshop-assets` 那条唯一路由。
- 编辑器装备页多一段「本包自带的图标（可选）」：键取自当前装备的 `trapId`，只让你从本包 `assets/` 里真实存在的图片里挑。
- 作者侧校验器加了 `ITEM_ICON_FILE_MISSING` / `ITEM_ICON_TYPE_UNSERVABLE` / `ITEM_ICON_UNKNOWN_ITEM`（warning）；
  「官方图标 id」取的是官方道具记录自己的 `iconId`/`trapId`（不是道具记录 id）—— 这一点在测试里专门钉住了。

## 0.7.2 — 2026-10-08

这一版按业主的反馈修上游 0.2.0 的商店/升级行为，并把**多语言配音拆成单独的发布附件**（主包瘦回一档）。

### 升级调度中心只多一个「空位」

0.2.0 按社区报告 item 19 改成「升级商店获得新的商店位时用新卡补上，而不是空着」（`player/economy.js _openLevelSlots`）。
业主对照官方后指出这是错的：「升级2本会刷新干员池和加入新干员，**升级商店等级加槽位应该是只多一个空位而不是直接多一个可
购买干员**」——升级买的是**栏位**，不是卡。现在：

- 升级后多出来的栏位是**空的**，已经刷出来的卡片原位不动；
- 空位由**下一次刷新**填上：手动刷新（`rollShop`）或下一回合开始的那次刷新；
- 免费挑选（策略 / 装备的挑选）与冻结行为不变。

`test/match/feedback5-shop-levelslots.test.js` 三条用例改成钉新规则；`matches` 那一族黄金值跟着变（bot 少拿一张卡，
商店随机数消耗随之改变），逐项核对后 `golden --update`，其余五族不变。

### 多语言配音改走发布附件

四种配音全塞进主包要多 ≈196 MB，现在拆开：

- 主包（`…-win-x64.zip`）只带**默认配音**（清单里的 `audio.voiceLang`，目前是中文，≈66 MB），比 0.7.1 小约 130 MB；
- 其余配音单独发 `…-voices-jp-en-kr.zip`（release 附加资产）：解压后把 `voice/` 覆盖到
  `app\public\assets\audio\voice\`，**不需要改任何配置**（清单里本来就列着这些语言）；
- 客户端更稳了：选中的配音**没装 / 缺这一句**时**回退到默认配音的那一句**（`audio.js voiceLinesFor` + `_playVoice`
  的 fallback），不会变成没声音；
- 设置里的「配音语言」只列**真的装了**的语言（`public/js/voiceDubs.js` 每种配音探一个 HEAD），没装的那几种会写明
  「从 release 页下载语音包」（`npm run assets` 的本地开发者不受影响：`--voice-langs` 装了就都在）。
- 新工具：`node scripts/make-voice-pack.mjs [--langs=jp,en,kr] [--include-default]`。

## 0.7.1 — 2026-10-08

这一版做三件事：**多语言配音**（玩家要的）、**修掉两个协防相关的真 bug**（业主反馈的），以及顺手的清理。

### 多语言配音：不同干员可以配不同语言

上游的四语言语音 dump（`cn` / `jp` / `en` / `kr`）以前一次只能装一种，清单里也只存一套 URL。现在：

- **清单新增两张表**：`audio.voice` 仍是**默认配音**（`audio.voiceLang` 说明它是哪种语言），
  其余语言进 `audio.voiceLangs[lang][charId][slot]`。四种语言的文件名完全一样，只有目录不同
  （`audio/voice/<语言>/<干员>/cn_0NN.mp3`），所以「换语言」就是换个目录。
- **两种入口**：**设置 → 配音语言** 选全局默认；任何干员的 **干员详情 → 配音** 单独覆盖（含「跟随默认」），
  点一下当场试听那一句。设置存在本机（`sp.pref.settings`），联机时不会影响别人。
- **一条都不缺就静默降级**：某种配音这台机器没下载、或上游本身缺这一句，`public/js/audio.js voiceLinesFor`
  会退回默认配音的那一句 —— 不会因为换语言变成没声音。
- **下载**：`node tools/fetch-assets.mjs --voice-langs=cn,jp,en,kr`（每种 ≈ 2,674 个文件 / 66 MB，四种 ≈ 262 MB）。
  `--voice-lang` 仍是「默认用哪种」，与 `--voice-all`（哪些槽位）正交。
- 实测覆盖：**中文 191 名干员 / 2674 条，日文 191 / 2674，英文 182 / 2548，韩文 182 / 2548**（英韩各缺 9 名最新干员，
  上游就没有）。清单里 10,444 条语音 URL **全部在磁盘上**。

### 修掉两个协防相关的真 bug

1. **协防时突袭干员跳不到队友的棋盘上**（玩家反馈）。上游 0.2.0 为了修「单人联防时突袭跑到对面场地」和
   「跳到临时整备区那一栏」把落点收紧成「只看自己的半场」，于是**双人协防时**突袭干员也跨不过去 ——
   而联防的敌人是从右半场一路走到左半场的，左半场的突袭干员因此够不到还在队友半场上的敌人。
   现在落点改成 **这一场里任何一名玩家的棋盘**（`Battle.onTeamBoard`）：队友的半场可以跳，
   **手牌行 / 临时整备区行、以及单人联防地图上「谁的棋盘都不是」的那半场，仍然禁止**（上游那两条反馈照样成立）。
   乌尔比安的 S3【移动】保持不变：它不需要敌人，放宽只会让它又停到红门口。
2. **工坊地图的 boss 回合会换掉抽中的首领**（协防 boss 战「不能正常刷新」的根因）。地图若用 `bossRounds` 指定
   每名首领的波次，却只写了自己做的那几个，旧代码会**退回「表里的第一个」** —— 于是关底生成的是另一名首领，
   而共享血池是按**抽中**那名首领的血量算的：领袖和血条对不上，若那张表指向普通波次，关底干脆不出领袖，
   血池永远打不空，只能靠掉血/加时结束。现在**只认抽中首领自己的那一项**，缺项就用该首领的官方波次。

### 顺手的清理

- 打包脚本与文档里「语音在 `voice_cn/`、默认关闭」的说法早已过期（0.2.0 的布局是 `audio/voice/<语言>/`，
  干员语音默认 0.8 = 开），一并改正；包内说明会按**实际装进去的语言**写多语言那一段。
- `jsconfig.json` 的 typecheck 切片把 Forge 独有的 8 个 `shared/*.js` 显式排除并写进 `types/README.md`，
  `npm run typecheck` 由红转绿（107 条都在这批文件里，与玩法无关）。

### 已知边界

- 工坊包自带的语音仍然只进**默认配音**；「包里给某个干员单独配一种语言」留到下一版
  （`pack.json` 的形状要扩，编辑器语音页也要跟着加语言选择）。
- 上游 0.2.0 的另一个隐患 `bossWaves` 复用：只有「休整期配对之后又有人离开」才会重掷波次，
  实测三个 seed 都走不到，暂不改。

## 0.7.0 — 2026-10-08

这一版把上游基线从 **0.1.3 抬到 0.2.0**：Forge 编辑器与工坊的成果原样保留，原作者那边更好的逻辑整体吸收。
上游 0.2.0 是个大版本（补位、自选编队、中英日韩四语言、自定义快捷键、精简包，以及几十条按官方数据与 PRTS 修正的规则），
所以本版的主要工作是**移植**，而不是新功能。

### 上游 0.2.0 照收的部分

- **补位**：标出自己没有的干员，开局由官方补位干员上场（8 名预备干员 + 郁金香、Sharp、Mechanist 等），盟约、特质、阶级与合成仍按原干员。
- **自选编队**：5 / 6 阶各选 2 名自己的 6★（71 名可选），调度中心到级后只出现在自己的商店里，召唤物按官方数量进手牌。
- **四语言**：标题页与设置里切换中文 / English / 日本語 / 한국어 / 繁體中文；另有语言包机制（`packs/<id>/pack.json`，`type: "lang"`）。
- **自定义快捷键**、**精简包**（约 22 MB，首次启动下载素材），以及上游拆开大文件后的代码结构
  （`server/http/`、`server/match/match/`、`server/match/player/`、`public/js/ui/gameLogic/`）。
- 上游的规则修正与 6 条**有意与官方不同**的调整一并生效（详见上游 CHANGELOG）。

### 我们保留并贴回 0.2.0 的部分

- **Forge 编辑器九个页面**（干员 / 地图 / 怪物 / 出怪 / 装备 / 盟约 / kit / 语音 / 包管理）、双语界面、实时校验、以模板新建、
  自己画攻击范围、一键按官方中位填数、保存旁一键试玩 —— 全部照旧，接口跟着 0.2.0 的新结构走。
- **工坊叠加层**：`workshop/<包>/` 的干员/装备/盟约/地图/出怪/怪物/kit/语音，包自带**语音**、**盟约图标**与**助战声明**，导入导出 `.zip`。
- **助战**（本项目自研）：服务端卡池、阶级名额、进店按阶级价购买出售、本局禁用不影响助战、结算页各队 MVP 说一句。
- **Option 署名**（`_meta`）与发行流程（整合包 + 源码包，`v<forge>-<上游>` 两段式 tag）。

### 语音：改用上游实现，只保留「包自带语音」

上游 0.2.0 自己实现了干员战斗语音，而且比我们那套完整：官方 15 种 `placeType` 里对外能播的 **12 个战斗槽位**（我们只有 6 个）、
按官方 `voiceTypeOptions` 的优先级 / 冷却 / 交叉淡入调度、cn/jp/en/kr 四语言 dump，连结算与「首次接敌」都接上了。所以：

- 删掉自研的 `tools/assets/voices.mjs` 与 `--voices` 开关，改用上游的 `tools/assets/audio.mjs` + `plan.mjs`
  （语音**默认就会规划**，另有 `--voice-lang=cn|jp|en|kr` 与 `--voice-all`）；
- 编辑器与工坊校验的槽位词表（`shared/constants.js VOICE_SLOTS`）换成上游客户端真正会播的 **12 个战斗槽位**
  （`start` / `faceEnemy` / `select` / `place` / `skill1-4` / `resultFour` / `resultThree` / `resultTwo` / `resultLose`）；
- **我们独有的一条保住**：`pack.json.voices`（包自带语音）仍然并进 `assets.audio.voice`；
- 顺手修掉一个真隐患：官方清单里「只有一句」的槽位写的是**字符串**，而我们原来的合并只认数组，会把那一句官方语音顶掉 ——
  现在先归一化成数组再追加。

### 素材：按作者给的 0.2.0 包补齐

下载工具按索引重算清单时会因为「部分文件拿不到」而**拒绝写出更小的清单**（`assets-report.json` 里 `manifestWritten: false`），
所以清单本身是对的，缺的是文件。从作者给的 0.2.0 包里补入 **358 个文件**（23.96 MB），全部是我们清单引用、磁盘上却没有的：

- **98 条干员语音**（26 名干员，其中 4 名几乎整条语音都缺）；
- **37 张骨骼贴图页**：补上后 75 个「模型缺贴图」的干员能正常渲染（`spineProblems` 归零）；
- **3 首 BGM**（联防的 `m_bat_corrosion_loop`、开战的 `m_bat_kazimierz2_1/2_loop`）、**55 张技能图**、6 张头像 / 8 张立绘 / 22 张召唤物头像；
- **12 张本机地图贴图与 117 个本机召唤物骨骼**，并采用作者的 `data/local-assets.json`（62 组，我们原来只有 23 组）
  —— 清单里那 39 个召唤物的官方模型因此才真正生效。作者的 37 个 atlas 比我们多一行 `size:`（与 PNG 实际尺寸一致），按上游测试要求一并采用。

核对：`data/assets.json` 引用的 **7969 个 `/assets` 文件 0 缺失**，**2674 条语音 URL 全部 HTTP 200 + `audio/*`**，
712 个 atlas 的贴图页与同名 skel 0 缺失。

### 移植中发现并修掉的两个真问题

1. **`SP_WORKSHOP` 失效**：`getData` 是进程级单例，而 0.2.0 的 import 链里已经有模块用**默认工坊目录**建过它，
   于是编辑器的「试玩」子进程读不到作者正在编辑的包。恢复「显式 `dataDir` / `workshopDir` / `SP_WORKSHOP` 时走 `loadData` 绕开单例」。
2. **一键试玩的深链解析漏贴**：`public/js/screens/lobby.js` 的 `parsePlaytestParam` / `DEFAULT_DIFFICULTY` 在合并时漏掉，
   `?playtest=1` 因此会整条失效。

## 0.9.4 — 2026-10-09

重剪宣传片时发现的：在 0.9.2 式的大图上点「自动寻路」，按钮态正常、没有报错，画布上却一条折线都没有。

### 「显示寻路」那一层从来没有数据可画

- 问题不在寻路：服务端两种尺寸都给得出路线（样板图放大到 23×27、部署区挪一行之后，`/api/stages/autoroute` 返回的路线与官方尺寸下逐字段相同）。
- 问题在**编辑器从来没要过那张表**：「显示寻路」画的是 `draw()` 里的 `rec.groundPaths`（引擎的流场寻路表），而那张表是**按需**算的（服务端 `opts.paths`）。官方图自带表所以看不出问题，工坊图（尤其新建或改过尺寸的）要请求才有。而 `preview()` 一直只发 `{ spec }` ⇒ 表恒为空 ⇒ 开关打开也永远没有线。点「自动寻路」还会顺手把开关打开（`state.showPaths = added > 0 || routes.length > 0`），正好撞在这个空上。
- 现在 `preview()` 发 `{ spec, paths: state.showPaths === true }`（开着才要，免得每次编辑都多算一遍流场），「显示寻路」打开时重新取一次表，关掉时只重画。
- 顺带说明一个**口径**（不是 bug）：官方尺寸下图子的表按官方那 12 对门派生，样板图自己的 S/E 不在其中所以是空的；大图按它自己的 S→E 配对，所以有 1 条。作者要看的是橙色那条**自己画的路线**，默认就画。

## 0.9.3 — 2026-10-09

业主拿到 0.9.2 之后自己开 3D 预览试了一下：「为什么现在的编辑地图的 3d 视角缩放没有感觉到 3d 地图在放大」。这是**一个真 bug**，而且是数学上的，不是手感上的。

### 滚轮缩放改对了参数

- 那台相机（`public/js/render/projection.js`，游戏本体那一台）是离轴针孔相机：屏幕上一点 = 画面中心 + `k·横向偏移/depth`，而焦距 `k = scale·dist`。在棋盘所在的平面（depth = `dist`）上，这个比例正好化成 **`scale`** —— 也就是说「屏幕上看多大」只由 `scale` 决定。老写法滚轮拉的是 `dist`，等于相机后退的同时把视场角等比放大：**画面里的棋盘一模一样大**（实测滚一格只差 **0.3%**，肉眼等于没动），而预览又把雾推到 400/1000，连「远近」的深度线索都没有，于是完全没反馈。
- 现在滚轮改 `scale`，`dist` **反向**跟随同一个倍率 —— `scale·dist` 不变 ⇒ 视场角不变，是「相机推近」，不是「换镜头」，缩放前后透视强弱一致。一格 **+10.4%**，六格约 **1.84 倍**；上下限按整图取景给（最多缩到 1/12、放到 12 倍）。
- `stats()` 补上 `scale`，以后「缩放在不在工作」有数可看，不必靠肉眼。

## 0.9.2 — 2026-10-08

业主的原话：「你能稍微把地图做的更大些吗，加入对大图的支持怎么样，这样图会更多样化」。

### 一、地图不再只有 19×21 一种尺寸

- **一张图自己带尺寸**：`size` 可选 **标准 19×21 / 大 23×27 / 特大 27×33**，中间任意尺寸也认（只能比官方大、不能小）。引擎世界是 27×33 的**画布**，地图是画布里的一个**窗口** —— 官方图仍然只占它原来那一块。
- **三块行带的锚法**：等待区贴顶 5 行、普通对战带「离顶第 7–10 行」、boss 带贴底第 1–5 行；**多出来的行全部进中间战场**（普通带与 boss 带之间）。联防与 boss 战场的宽度跟随整张图，所以大图的联防 / 最终攻势战场比以前宽一大截。
- **分区的行能挪、列不能挪**：棋盘 9 列、两个 boss 半场在 col 10 相接、镜像轴 20，列一挪对战镜像就对不上，所以三块部署矩形的列被锁死（2–10 / 2–10 / 10–18），作者挪的是行（以及等待区、各战斗矩形的行）。
- **大图走它自己的门**：寻路表按这张图自己的 `S` → `E` 成对组合（最多 12 对）在整张图上推导，而不是官方那 12 对固定坐标。

### 二、官方零变化是算出来的，不是承诺

- **唯一数据源**：`shared/layout.js` 的 `layoutForSize(19×21)` 解出来的每一个数字（三块部署矩形、`normal`/`unite`/`boss` 三个战斗矩形、等待区、镜像轴）与历史常量**逐字段相等**，棋盘↔地图的映射（普通恒等、boss 减 7、bossR 过 20 列镜像）也**逐格相等** —— `test/layout.test.js` 把这批等式钉住了。
- **记录只在必要时才变**：`layout` 仅在作者真挪过分区（或尺寸大于官方）时写进 `stages.json`。官方尺寸、没挪过的图，记录与 0.9.1 **逐字节一样**；`data/*.json` 一个字节都没动。
- **引擎与素材零变化**：11 张官方图、素材、语音、golden 全都照旧；全量测试从 6071 涨到 6109 条，新增的 38 条守大图与上述等式，旧的一条没删（测试里原先写死的「21 列步长」改成引擎的画布步长 —— 常量改名，不是行为变化）。

### 三、编辑器：尺寸档 + 分区编辑

- **尺寸档**：画布上方新增一条尺寸条（右栏「地图尺寸」面板同一入口）：**标准 19×21 / 大 23×27 / 特大 27×33**（图里声明过自定尺寸时多一项「自定（{0}）」），旁边是当前尺寸文字与「分区」按钮。换档时旧字形**按左下角对齐保留**、新窗口里多出来的带子填空气（`-`），分区重置成该尺寸的默认布局，然后立刻重推导 —— 3D 预览与分区视图一起跟上。
- **分区编辑**：进「分区」模式后画布只画分区（地形压暗）：三块部署矩形、五个战斗矩形、怪物等待区、镜像轴，每条边/每个角都有可拖的点，方向键微调选中的那条边；右栏是 12 个 `r0/r1/c0/c1` 数字框 + 「重置为尺寸默认」，现场跑 `validateStage` 只筛 `layout.*` 的问题，好就显示「✔ 分区合法」。**部署矩形只给整块上下挪**（深度恒 4 / 5，`c0`/`c1` 只读，镜像轴只作标注）—— 只挪一条边会做出 5 行的普通矩形，而 `normalizeLayout` 对形状不对的矩形会静默退回默认，作者会看着自己的改动被吃掉。
- **官方零变化**：`currentSpec()` 里 `size` 只在 ≠ 官方时写、`layout` 只在 ≠ 该尺寸默认时写，所以「打开官方图、随手保存」写回去仍是一条**没有 `size`、没有 `layout`** 的记录（实跑 HTTP 存盘复验过）。

### 四、客户端：按这张图自己的窗口画

- **只画这张图**：`render/tiles.js` 里写死的 `ROWS = 19 / COLS = 21` 没了 —— 画布（27×33）上的格子照样铺，但只有**地图自己的窗口**是「作者画的」，窗口外只上底色不画斜纹（斜纹的意思是「这里画了空气」，铺满整块画布会把图淹掉）。3D 棋盘与地面平面按同一窗口建，背景以岛的包围盒为中心（不再假设 21 列宽）。
- **取景**：官方布局仍然用**官方那台相机**（按官方 19×21 拟合的 configBlackBoard 参数）；一旦这张图的分区不是官方布局（大图、或挪过行），就用仓库里本来就有的 `fitCamera` 取景 —— 不另造光学。休整期的取景跟的是**这张图自己的普通带**（官方算出来仍是历史上那个 `{r0:7, r1:12, c0:0, c1:10}`）。
- **等待区（预览围栏）**：矩形取 `stage.config.enemy_place_rect`，没有就取这张图自己的 `pen`；「上/下区」由这个矩形的两格敌方入口**在客户端自己推**（服务器那句 `preview.gate` 是按官方带算的，只当兜底）。
- **棋盘↔地图映射**：客户端也走 `layoutOf(stage)`（缺省仍是官方），所以它与服务端**逐格相等** —— `test/match/playtest5-deploy.test.js` 的交叉断言照旧绿；DOM 兜底视图（`ui/fallbackField.js`）同步跟上。
- 新增 19 条客户端渲染测试（`test/render/bigmap-client.test.js`）：官方记录走每个新入口都是历史数字，一张真 23×27 的图只解析/只画自己的窗口。

## 0.9.1 — 2026-10-08

这一版全部来自业主拿到 0.9.0 之后**自己在编辑器里做了一张图**的实测反馈（原话：「我新建了一张地图，没有编号不让开图，有编号需要工坊包，下面那个工坊包新建没有用」）。规则与战斗内核照旧一行未动。

### 一、新建一张图 → 试玩，不再绕圈

此前那条路要走三步、每步都可能撞墙：**没填 id 不让保存 / 有 id 没有工坊包不让保存 / 存过才允许试玩**，而地图页「保存到」里的「＋ 新建一个包…」**根本没接上建包的那一半**（`packSelect` 少了 `create`），点了什么都不会发生。

- 地图页的包选择器现在与干员页同一套：手输 id **立刻建包**、旁边多一颗「＋ 一键新建工坊包」（自动推不撞名的 id），失败时把服务端的原话就地报在输入框下面。
- 「**▶ 保存并试玩这张图**」把前置条件自己做掉：缺 id 就按名字推一个（中文名退回 `my_map`，重了依次 `my_map_2`…）、没存进当前包就先保存（**一个包都没有时先一键建一个**），然后才起服务器。保存失败就不起，错误原样留在右栏。
- 「保存并推导」也不再因为「没填 id」禁用：点下去会自动起一个 id。保存完会重新推导一次，右栏不会再把保存前那份预览（例如 `BAD_ID`）挂在那儿。

### 二、能不能部署，终于说得清了（业主：怪物出口那一行的路为什么放不了干员）

引擎的判定是**两件事相乘**：这一格在不在**部署矩形**里（`normal` 9–12 × 2–10；`bossLeft`/`bossRight` 1–5 行左右各半），以及地块自己的高度/可部署属性。作者只画道路、只看颜色时，第二件看得见、**第一件看不见** —— 于是「是路就能放干员」这个直觉在矩形外当场失效。

- 2D 画布把**部署矩形画出来了**：虚线边框 + 名字（普通对战部署区 / boss 左半 / boss 右半），跟着「显示部署区」开关走。
- 鼠标停格那行现在报三件事：坐标、字符、**「在 普通对战部署区 内 · 可放地面干员（近战位）」**或**「不在任何部署区内：敌人会走，但放不了干员」**。
- 推导结果里新增一条提示：**部署行里有 N 格「可放地面干员」的地块落在矩形外**，附一颗「跳到第一格」把它摆到视野中央（业主的困惑就是这一条，与其让他猜，不如点出来）。
- 口径写进 `shared/stageAuthoring.js` 的 `roadsOutsideDeployRects`：只报**有矩形的那些行**（1–5 与 9–12）里落在矩形外的可部署地块 —— 怪物等待区（14–18 行）整片本来就不该能部署，报它只是噪音。

### 三、一张 19×21 拆成三个区来画

业主：「为什么要把怪物等待区、普通对战、boss 对战写在一整张大图上，这很难分辨，不如直接把它拆成三块让人画……然后保留这个三合一画面，用来给专业用户检修」。

这三个区在数据与引擎里确实是**同一张 19×21 的行带**（`server/match/board.js` 的 FIELD 与 `BOSS_ROW_OFFSET`、`server/match/waves.js` 的预览围栏锚点），所以做法是**分区视图**而不是三份数据：

- 工具条新增「区域」：**怪物等待区（预览围栏，14–18 行）/ 普通对战（9–12）/ boss 对战（1–5）/ 整图（专业检修）**。选一个区就把视口框到那一带、**区外一律压暗**、并在带的左上角写上区名；「整图」就是原来那张三合一画面。
- 默认进入的是「普通对战」（业主说糊在一起的就是它）；作者自己缩放/平移之后视图归他，窗口尺寸再变也不会抢方向盘。
- 「**从官方图取这一区…**」：把官方图（或样板图）里属于当前区的行整段抄过来，**其它区一个字节都不动**，模板的图例一起并进来（官方图用到的字形不一定在我们的默认图例里）。这就是「找几张官方图拆开当模板，允许用户选择」。

### 四、3D 预览为什么不能绕圈转（业主问的，没做）

**不做 yaw**：这一层用的是**游戏自己那台相机**（固定朝向的投影相机），俯角 + 平移 + 远近就是它全部的控制面 —— 能绕圈转的相机拍出来的就不是「游戏里长什么样」了，而这正是这一层存在的理由。页面提示里写明了这一点，省得下次再问；换角度仍然用现成的五个取景（全图 / 俯视 / 游戏视角 / 侧视 / 近景）。

## 0.9.0 — 2026-10-08

这一版只做两件事：**把创建工坊包从「先做一条内容」里解耦**，以及**把地图编辑器做成能用的样子**。规则与战斗内核一行未动。

### 一、创建工坊包不再需要先新建一条内容（业主的紧急问题）

此前工坊包只有一个来源：**保存第一条记录**时服务端顺带建目录。于是干员页那颗「新建工坊包」实际是「先做一条干员」——
而且它还会把作者正在填的表单清空，逼人重填。

- 新增 `POST /api/packs`：包目录与 `pack.json` 立刻落盘（`content: []` 合法），与任何内容无关。
- 编辑器里的「新建工坊包」现在有两种用法，都**不碰当前表单**：手输 id（校验通过后立刻建包）与「＋ 一键新建工坊包」
  （自动推一个不撞名的 id）。包清单**就地**补一条，不整页重载，光标与已填内容都留着。
- 各内容页「保存到」下拉里的「＋ 新建一个包…」同样变成**立刻建包**（`editor/ui/packPicker.js` 的 `createPack`），
  失败时把服务端的原话就地报在输入框下面，不会把 id 塞进下拉。

### 二、地图编辑器（业主的紧急问题）

1. **看得见整张图**：2D 画布不再写死 672×608。新增视口层：默认 **fit-to-view**（整张 19×21 塞进容器），
   滚轮/双指缩放、中键或空格拖平移、「适应」一键复位；点选与画笔在任何缩放平移下都落在同一格。3D 画布同样跟随容器。
2. **新建就能看 3D**：不再需要先把地图存下来（此前 3D 只吃服务端已推导的记录，新建时永远是空白）。
   现在用本地 spec 现拼一个最小记录先画出来，棋盘取景等模型装好后自动收敛。
3. **不许默认有寻路**（业主口径）：派生的 `groundPaths` / `groundPathsWithDevices` **只在作者画过路线时才生成**
   （`deriveStage(spec, { paths })`），新建的空图不再自带 12 条官方门路径；界面上那三处「寻路 N 条」也不再默认显示。
   新增 **`POST /api/stages/autoroute`（只算不写）** 与工具条上的「**自动寻路**」按钮：点一下才按本图的
   S（入口）配最近的 E（保护目标）求一条跟着道路走的折线，追加进 `spec.routes`。没有 S/E 时**什么都不画**并说明原因。
4. **地块规则可自定义**：右栏新增「地块图例 / 部署规则」面板，逐字符改 `height` / `buildable` / `passable`（只给白名单取值），
   旁边实时显示推导结论（可放近战位 / 只能远程位 / 不可部署）。新增 **空气字符 `-`**：语义等于「地图外」
   （不可走、不可部署），编辑器里画成暗底斜纹而不是墙 —— 地图外的区域由作者自己圈。
5. **地面与高台**：默认仍是「地面不能放干员、道路可以、高台可部署、不可部署的用阻隔」；新增每图开关
   `options.groundHighGround`（复选框「地面也能放远程位」），把「普通地面能不能放高台干员」交给作者。
   推导层同时补上了 `LOW + buildable:'RANGED' → 远程位`，与引擎 `buildDeployMap` 对齐（此前两边判定不一致）。
6. **地图种类**：新增「地图种类」下拉 —— 单人（默认，不写任何键）/ 联防（1 人）/ 联防（2 人），
   `kind`/`helpers` 现在会**透传进记录**（此前被推导层丢掉，工坊图因此永远声明不了联防）。首领战不是地图种类：
   在「回合绑定」里给某一回合绑上首领出怪表，那一回合就是首领战。

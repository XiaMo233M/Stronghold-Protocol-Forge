## 0.6.4 — 2026-10-07

修一句**说错的数字**，再把介绍图放进仓库。游戏本体（上游 0.1.3）没动。

### 分支计数：说「只列这个职业的分支」就不该把外来的值算进去

0.6.3 把分支下拉改成按职业联动之后，提示写的是「只列「狙击」这个职业的分支（共 8 个）」。**狙击只有 7 个分支。**
第 8 个是切职业时**故意留下来**的旧值（比如从重装过来的 `protector`）—— 留着它是对的（不静默清空），
错的是把这一项也算进「这个职业的分支」里。现在：

- 计数报**这个职业真实的分支数**（`subOpts` 在塞回旧值**之前**取长度）；
- 那条例外说明补上后半句：「……**它留在下拉里，不会被自动清掉。**」
- 手填一个官方分支表里没有的 id 时也给同一句保证（这时没有「它属于哪个职业」可说）：
  「当前值「xxx」不在官方分支表里，仍留在下拉里（不静默清空）。」

`test/operatorForm.test.js` 的那条用例补了三条断言锁住它：切换职业后计数仍是本职业的数字、下拉里确实多出一个旧值、
以及手填未知分支时走的是另一句说明。

## 0.6.3 — 2026-10-07

这一版按「**更简易上手**」来做：分支跟着职业走、攻击范围可以自己画，另外补了三处让白纸起手不那么劝退的东西
（分段导航与折叠、一键按官方中位填数、保存旁一键试玩）。游戏本体（上游 0.1.3）没动。

### 分支跟着职业走

官方数据里 **57 个分支各归一个职业**（没有一个是跨职业的），所以「先选职业，再从这个职业允许的分支里挑」
是唯一说得通的顺序。现在：

- 分支下拉**只列当前职业的分支**，改职业立刻换清单（下面还写明「只列「狙击」这个职业的分支（共 7 个）」）。
- 当前值不属于新职业时**不静默清空**：它留在下拉里，并有一条说明
  「这个分支不属于「术师」，它属于 狙击」—— 记录能保存，但职业光环与分支行为可能对不上。
  静默清空是一次无声的数据丢失，所以宁可多说一句。
- 手填框保留：官方没有的分支 id 也能写。
- 联动表由 `/api/state.subProfessions` 给出，且**从全部记录算**（不是只从可见干员）——
  只在一条不可见记录上出现的 `pusher`（推击手）因此也在候选里；从可见数据推就会漏掉它。

### 攻击范围：预设之外可以自己画

- 范围字段旁边多了一个**画板**：7×9 格（x∈[-3,3]、y∈[-2,6]，官方 258 条带范围的记录都画得下），
  点格子点亮/点灭，底纹显示推导出来的形状（一眼看得见自己改了几格），格子是 `<button>`（键盘可达）。
- **原点那一格去不掉**：干员必须站在自己的范围内 —— 空范围谁都打不到，而引擎不会为此报错。
- 画出来的就是记录里的 `rangeGrid`。**五处范围字段共用这一套**：干员攻击范围、干员特性自带范围、
  精锐特性自带范围、模组特性范围、天赋改写自带范围 —— 所以「特殊情况」在哪儿都能自己画。
- 画板装不下的超大范围（模板带来或手写）不会被丢掉：界面上会说明还有几格在板外，它们原样保留。
- 攻击分类四项的下拉也写明「列的是**引擎认识的全部取值**」：那是引擎的完整词表，不是我们挑的几个。

### 更简易上手的三处

1. **表单分段 + 折叠 + 顶部「跳到」**：干员页已经十段长，「找不到」是它的第一号可用性问题。现在不常改的三段
   （精锐 / 模组 / 盟约）默认收起，顶上一条「跳到：身份 外观 范围·分类 数值 技能 天赋 精锐 模组 盟约 校验」
   一点就展开并滚过去。折叠状态记在内存里，不会被每 250ms 的自动校验重画弹回去。
   （做法参照通用的那两条：[渐进披露](https://webaim.org/techniques/disclosures/)、
   [长表单的分组与导航](https://cfpb.github.io/design-system/guidelines/designing-forms)。）
2. **数值一键按官方中位填入**：白纸最劝退的是「这八个数字该填多少」。现在每个数值栏一个按钮，
   一键把官方同职业的中位数落进去（普通与精锐各有自己的按钮），起手就有一份官方量级的数值可改。
3. **保存旁一键试玩**：`▶ 试玩` 直接起一局（已经在跑就先停再起，意思就是「加载我刚写的内容」）并在新标签页打开，
   省掉「切到包管理页 → 点试玩」那两步。

全量测试数字见发布说明（`npm test`）。新增：`test/operatorWizard.test.js` 的分支联动与画板坐标 5 条、
`test/operatorForm.test.js` 的分支联动 / 画板 / 分段折叠 / 中位填数 / 一键试玩 5 条、

## 0.6.2 — 2026-10-07

这一版把工坊剩下的两处「看得见的缺口」补上：**行为层 kit 终于有手把手的创作 prompt**（而且那份示例是被测试真的
跑过一遍的），**新盟约不再只能是一个圆点**（包可以自带图标）。顺带把干员特性的自带范围也接到了界面上。
游戏本体（上游 0.1.3）仍然没动。

### 行为层 kit 的创作 prompt（`docs/prompts/kit.md`）

行为层是唯一**本身就是代码**的内容种类（`kits/<chessId>.js`），也是唯一一种「写错不报错、只是什么都不发生」
的地方最多的一层。这份文档把写对它需要的东西收在一处：

- **Kit 形状**：`{ skill, skills, talents, trait, install }`；以及那条最容易踩的规则 ——
  **返回了 kit 就必须自己给出 `skill`**（缺省技能不会回退到通用 kit，干员会永远不放技能）。
- **四条硬规则**：默认导出 / 零 `import` / 确定性且无环境依赖 / 钩子名必须是引擎真的会 emit 的名字。
  每条都写清「违反之后你会看到什么」——它们是静默失败，不是报错。
- **32 个钩子的词表**：从引擎的 emit 现场抠出来的 `ctx` 形状与用途（`hit` 改 `dmg`、`fatal` 设 `prevented`、
  `beforeStatus` 可取消、`layerGain` 改层数…），以及「`{ owner: unit }` 一定要写」这条。
- **一个完整的示例 kit**，并且它**真的会被跑一遍**：`test/kitPrompt.test.js` 从 markdown 里把它抽出来，
  先过静态校验，再注入一场真实战斗 —— 技能真的激活、真的击杀、buff 真的叠到 5 层封顶、技能结束真的清空。
  文档里的代码因此不会腐烂（API 改名或钩子词表变动都会让测试红）。
- 词表与引擎的一致性也有守卫：漏写任何一个 `HOOK_EVENTS` 里的钩子都会失败。

### 盟约图标：包可以自带（`pack.json` 的 `bondIcons`）

客户端按**盟约 id** 从 `data/assets.json` 的 `bonds` 取图，而一个包没法往 `assets.json` 里加条目 ——
于是**新增**的盟约在盟约条上只能是一个圆点，编辑器也只能提示「你没法给它配图」。现在这条口子开在 `pack.json` 上
（与语音同一套做法）：

```json
{ "id": "my-icons", "license": "CC0-1.0", "content": [], "bondIcons": { "myShip": "bond/myShip.png" } }
```

- 装载时叠加层把它并进 `assets.bonds`（`workshopBondIconIndex` / `mergeWorkshopBondIcons`），URL 走
  `/workshop-assets/<pack>/<路径>` 那条唯一的包素材路由 —— **客户端不需要任何改动**。
- **覆盖官方 = 换掉官方图标**；新增的 id 直接加进去。两张图抢同一个 id 时按包 id 排序第一个赢，后一个包报一条错误
  （静默覆盖会变成「换个包顺序图标就变了」）。
- **只带图标的包是合法的包**（`content: []`）—— 这里顺手堵掉一个真的会踩的坑：加载器原本只认「有数据文件或有语音」
  的包，只带图标的包会被**静默丢弃**（加载「成功」但什么都不贡献）。
- 编辑器盟约页新增「本包自带的图标」：只列本包 `assets/` 里**真的存在**的图片，保存前挡掉不存在的文件；
  路径穿越、非图片、坏 id、给不存在的盟约配图都是 400 且一个字节都不写。

### 干员特性的自带范围

特性的「自带范围」（不是干员的攻击范围，引擎里由特性定义 —— 例：散射手用它定义正面那一圈）现在可以在干员页编辑：
普通态一个下拉，精锐态在「精锐特性不同」勾上之后再给一个（留空＝与普通同一片）。此前它只能靠模板带过来。

### 其它

- 测试新增：`test/kitPrompt.test.js`（4 条，示例真的跑战斗）、`test/workshopBondIcons.test.js`（13 条，
  含端到端 HTTP —— 合并后的 `assets.json` 里那条 URL 真的取得到图片）、`test/bondEditor.test.js` 的图标接口 4 条、
  干员页「特性自带范围」1 条。
- 全量测试数字见发布说明（`npm test`）。

## 0.6.1 — 2026-10-07

接着 v0.6.0 补完干员编辑器的最后两个洞：**精锐（精英 2）单独的那一份**终于能编，
**模组的范围类字段**也不再只能靠模板带过来。游戏本体（上游 0.1.3）仍然没动。

### 精锐（精英 2）与普通不同时：三个开关

数值一直是两套，而**特性、天赋、攻击范围**在 spec 里是**可选**的第二份。官方数据说明了这不是理论问题：
可见的 112 位干员里有 **33 位两态天赋不同**（常见：弹药上限 +2 → +3）、**2 位精锐特性不同**、**2 位精锐攻击范围不同**。

- 干员页新增「精锐（精英 2）与普通不同时」面板，三个开关：**精锐特性不同 / 精锐攻击范围不同 / 精锐天赋不同**。
- **不勾＝两态共用一份**（字段根本不写）；勾上时以普通那一份为起点（天赋是深拷贝、范围是普通那份的副本），
  **取消勾选＝把字段删掉、回到共用**。留一份与普通一模一样的副本不会报错，但 spec 会变脏，别人也看不出精锐改了什么。
- 天赋那一份是**完整列表**（新增的编辑器与普通那份共用同一个实现），所以精锐可以有两态不同的天赋条数。
- 三个字段都只写进精锐记录：`traitGolden` → `traitBase`、`talentsGolden` → `talentsBase`、`rangeGridGolden` → 精锐的 `rangeGrid`。

### 模组的范围：特性自带范围 与 天赋改写自带范围

v0.6.0 的模组卡还差两个范围字段，它们都是引擎真的会读的：

- **特性自带范围（`traitOverride.rangeGrid`）**：特性自己那片范围（不是干员的攻击范围）。官方 4 位干员的特性、
  6 个模组的特性覆盖用到它（例：散射手用它定义正面那一圈，`server/sim/professions.js`）。
- **天赋改写自带范围（`talentChanges[].rangeGrid`）**：官方那些「攻击范围扩大」的模组就是靠
  `talentIndex: -1` 的那条改写 + 这个范围（`shared/loadoutRecord.js` 的 `attackRangeGrid`）。
- 两处都是同一个范围形状下拉（带「例：能天使」那种样本干员）+ 小格阵预览，留空＝不改范围。

### 顺手修掉的两处文档数字

- `docs/prompts/operator-pack.md` 里「官方 38 位两态天赋不同 / 26 位特性不同 / 5 位范围不同」是错的
  （那是别的口径的数字），改成与上面一致的口径。
- `README.md`/`docs/EDITOR.md` 里「官方 266 个干员可当模板」也不准：模板选择器列的是**112 位可见干员**
  （266 是 `data/chess.json` 的全部记录数，含精锐与不可见记录）。

### 其它

- 新增测试：`test/chessModules.test.js` 增「精锐那一份只写进精锐记录」「不写时两态共用」「可见干员数目漂移守卫」；
  `test/operatorForm.test.js` 增「精锐三件套的勾选/起点/取消」与「模组两处范围」共 2 条真跑用例。
- 全量测试数字见发布说明（`npm test`）。

## 0.6.0 — 2026-10-07

干员编辑器这一版被补成**完整的一层**：职业/分支/位置有中文（双语）、攻击分类可以按需覆盖、
**模组可以创作**（官方 184 个模组的数据形状终于有界面），外加盟约勾选与配套的创作 prompt。
游戏本体（上游 0.1.3）仍然没动。

### 干员页：职业、分支、位置全部汉化（中英双语）

- 职业下拉显示「**近卫 WARRIOR**」「**重装 TANK**」——中文名给人看，大写枚举才是记录里写下去的值。
  这份名称表在 `shared/chessAuthoring.js`（`PROFESSION_NAMES` / `POSITION_NAMES`），
  有漂移守卫钉在数据上：职业枚举写错会让该干员的所有 `profession === '…'` 光环与天赋**静默失效**。
- **分支变成下拉**：57 个官方分支按中文名（`subProfessionName`）排序，显示成「速射手 · fastshot」，
  不再要求作者手打英文 id；仍保留一个手填输入框（自定义分支用）。
  数据里只有中文名，所以英文界面下这一栏显示 id 本身 —— 猜一个英文名只会让人以为自己填错了。
- 位置下拉显示「近战 MELEE」「远程 RANGED」。

### 攻击分类：推导有据，覆盖有口

攻击范围与伤害类型一直是由职业与分支**推导**出来的，但「同分支却不一样」的官方特例不少。现在：

- 页面上写明推导结果（伤害类型 / 攻击方式 / 可打空中），并新增**覆盖**区：`dmgType` `attackKind`
  `projectile` `canHitFly` 四项都能钉住，留空＝用推导值。覆盖写进记录时校验会给一条 `CLASS_OVERRIDE` 警告。
- **范围小格阵的默认形状按「生效值」算**：把攻击方式覆盖成 `melee` 后，默认范围立刻变成近战两格 ——
  以前这一格只是照 `classify()` 画，作者会看到一个假的默认范围。

### 模组（`modules`）：官方 184 个模组的数据形状有界面了

- 干员页新增模组卡：id / 名称 / 类型 / 图标 / 等级 / **数值加成** / 特性覆盖 / 天赋改写，可增删。
- 摸清并落地了一条容易被忽略的规则：精锐记录的数值/特性/天赋是**三件套两套**——
  `statsBase`/`traitBase`/`talentsBase` 是「不带模组」的原样，`stats`/`trait`/`talents` 是
  **默认模组烘进去之后**的样子（`shared/loadoutRecord.js` 的 `composeStats` / `composeTalents`）。
  界面上「加了模组之后变成多少」那一行用的就是同一个函数，所以显示与引擎必然一致。
- 模组的 `attr` 键做成下拉（`MODULE_ATTR_KEYS`，8 个真键，有数据漂移守卫）：写错键名不会报错，
  但**一个数值也不加**——这是模组最容易踩的静默坑。
- 勾了「默认」的那一个才会被烘进精锐记录（勾两个是校验错误，界面勾一个会自动取消另一个）。
- **全量往返保真**：`specFromChessRecord` 现在把模组整套搬进模板（含富文本 `descRaw`、`traitBbStr`、
  `rangeGrid`、稀疏天赋 `index`、`typeIcon` 的大小写例外），并以模板新建后**逐字节**还原官方记录；
  官方 110 位带模组干员的往返一致，112 位可见干员里只允许 1 位已知例外（集成战略专用记录）。

### 干员页可以勾盟约了

- 新增「盟约 bonds」区：官方 23 条 + 本包自己写的盟约（标「本包」），可搜索、可勾选；
  模板带过来的官方盟约默认就是勾着的，取消即退出。查不到的 id 会当场警告（游戏里不会有任何效果）。

### 堵住三处静默失败

1. **改了天赋说明却没生效**：官方 199 条天赋里有 56 条的 `descRaw`（富文本原文）与 `desc` **不同**，
   而派生层优先读 `descRaw`。界面上只改 `desc` 的话，记录里一个字都不会变。
   现在编辑任何一处纯文本（干员特性、天赋说明、模组特性/说明/天赋改写）都会**连 `descRaw` 一起改**。
2. **模组功能键名写错**：见上（`MODULE_ATTR_KEYS` 下拉）。
3. **`subProfessionId` 手打错**：现在从 57 个官方分支里挑。

### 创作 prompt

`docs/prompts/` 补上了这一版新增能力的写法，让别人（或 AI）能直接产出合法内容：

- `operator-pack.md`：新增**模组**、**攻击分类覆盖**、**盟约成员**、`traitGolden`/`talentsGolden` 等字段说明。
- `README.md`：新增**盟约 spec 形状**（`bond-specs/<id>.json`）一节，并在 `content` 列表里补上 `bonds`。
